## 最小例子：一段可点击的调查提示

在独立测试工程中准备已有的“资料面板”和“读取线索”方法，在一句旁白的不同文字位置分别配置打开界面与调用方法。先用 2.3 Beta 编辑器配置并保存，再让 AI 比较该句 `content` 及真实动作参数。正常播放，分别点击，确认只触发目标动作、没有多次注册；再检查读取存档后的显示与方法结果。网页链接使用明确用途的 HTTP/HTTPS 地址，不包含凭据。

这只是配置与验收方法，不提供推测的 JSON 或现成资产。当前 [JSON 参考](https://docs.avg-engine.com/reference/script-json)、[对白](https://docs.avg-engine.com/manual/writing/blocks/dialogue)、[历史 API](https://docs.avg-engine.com/extensions/runtime/history)未必同步公告中的全部字段；缺少签名时先查实际 SDK。独立的“打开外部链接”Block 与行内超链接分别判断，不能拿其重放规则替代超链接实测。

从 [AI 扩展指导](https://docs.avg-engine.com/extensions/llms.txt)和[运行时接口](https://docs.avg-engine.com/extensions/api-context)进入，在目标 `sdk/index.ts`、`sdk/sdk-context.ts` 核对历史追加和相关命名空间。记录 SDK 指纹与来源，不把 Beta SDK 复制到稳定版。本轮官方初始化的2.3.0-beta.1 SDK已确认历史追加声明及来源，并完成下文有限运行。数据列表项点击动作的保存样本和参数仍为 **UNKNOWN**，按真实类型／样本补齐。

其他 Beta 版本不能仅按大小比较就复用本页；回[通用兼容](../version-compatibility.md)刷新版本依据。未列出的能力按当前任务补证，不要求先验收整个 Beta 才开展已有功能的制作。

## 本版原生调用证据

2026-09-30，Windows 实际 FileVersion 与 Studio 原生界面均为 2.3.0-beta.1。在官方新建空白工程的合成章节中观察：

| 调用结构 | 本轮原生结果 | 验证入口 |
| --- | --- | --- |
| main → A，无循环 | 主线开头 → A 内容 → 主线后续 | 调试运行与 OP 视图 |
| A → main，main 不回调 A | A 开头 → main 内容 → A 后续 | 原生片段实时预览与 OP 视图 |
| main → main | 两条旁白各播放一次；OP 共4条，无重复展开 | 调试运行与 OP 视图 |
| main → A → main | A 内容播放后返回主线，没有重复主线开头 | 调试运行 |
| main → A，A 自调用 | A 开头／后续各一次，再回主线 | 调试运行 |

下拉可选 main／自身，保存目标 UUID 保留。循环用例表现为回边未展开，不能据此认定所有循环算法或最大深度。官方文档及界面仍声称最多展开30层，与本轮自调用结果不一致。不要依赖自调用实现可条件退出的递归。此证据不覆盖 branch／if／扩展流接口、Stable、独立玩家或导出；其他 Beta 版本需另行核对。

## 2026-10-01 首轮原生编辑、重启与导出补验

实际 Windows Studio **2.3.0-beta.1**，官方新建空白隔离工程，仅使用原创色块与合成文字。以下是本轮新结果，历史 main／循环用例没有重跑。

| 项目 | 保存或来源依据 | 实际运行与限制 |
| --- | --- | --- |
| 卡内选项 | 原生新增、改文字、Ctrl+B 粗体、文案中的 `{游玩天数}`、把目标 A 改为 B；`choices` 仍为 JSON 字符串，文案保存 `[b]CARD_VAR_{游玩天数}[/b]`，目标保存实际片段 ID | 调试、Windows 玩家与 Web 玩家显示粗体 `CARD_VAR_0` 并进入 B 独有文字；首轮未测选择后赋值、自定义变量或全部样式；本轮补验见后节 |
| 双图层场景 | 新建空场景后原生导入两张背景，`scenes.json` 为 version 2、一个场景两层，章节 scene 指令引用真实场景 ID | 场景编辑器、调试及两个导出玩家均显示蓝色底图与透明橙色叠层；没有测试从背景列表直接创建或分别拆场景、任意层序和全部尺寸 |
| 旁白界面链接 | 原生超链接选择“显示界面”，目标为实际系统历史槽 `slot:internal.system.history` | 调试点击打开历史界面且剧情位置不推进；仅这一旁白和界面，没有测试外部网页或角色对白 |
| 旁白方法链接与历史 | 原生“调用扩展方法”选择已注册方法；保存 `type: method`、真实 `扩展ID/方法ID` 与 `paramsJson: "{}"`；配套 SDK 来源见下文 | 调试两次点击各追加一条 SINGLE 和批次 A、B，同文不自动去重，剧情位置不推进；两个导出玩家各一次点击也显示三条；未测带参数、失效目标或列表项点击 |
| 同会话快存快读 | 六条追加历史后快存，推进到选项再快读 | 返回原旁白、六条历史仍在；只证明该运行会话的观察，不据此称为历史持久化 |
| 真实重启 Studio 后快读 | 关闭应用、重开隔离工程、开始运行并快读同一快存档 | 剧情位置恢复，但此前六条追加历史均未恢复；再次点击方法仍追加三条。仅一个调试快存档，不推广到全部存档方式或导出玩家重启 |
| 本地导出 | Studio 构建中心选择 Windows x64 与 Web，原始产物及两份 ZIP 均生成 | Windows 独立进程和本地 Web 页分别播放图层、方法和 B 路线；未测 Android、Steam、线上部署、全部结束行为及玩家持久状态 |

官方新建工程的 `project.json.version` 和 `engineVersion` 都是 `1.0.0`，实际 EXE FileVersion 与界面为 `2.3.0-beta.1`。字段确切语义尚未确认，保留原值；不能将这两个字段直接作为宿主版本。

配套 SDK 由该版 Studio 官方扩展向导“初始化程序”取得：`SDK_VERSION` 为 `2.3.0-beta.1`，清单要求 `^2.3.0-beta.1`。初始化 SDK 的 30 文件原文保全，其中随当前宿主提供的 29 文件逐项一致；新增探针从源码构建、原生刷新后调用，不手改发行 dist。声明、构建、来源、保存样本与运行分别核对，没有把另一版 SDK 移到本工程。

`history.append(entry: HistoryEntry)` 与 `history.appendBatch(entries: readonly HistoryEntry[])` 均返回 void，`HistoryEntry.text` 必填；本次只用了 text。SDK 说明它们追加当前运行历史，不自动持久化或去重。本次重启结果与此一致，不能直接定性为引擎缺陷。需要保留追加记录的扩展须另外设计保存与恢复，并单独验收；本探针没有实现持久化。空批次、通知次数、可选历史字段、数据列表项点击及其他 SDK 接口仍未测试。

这些结果仅覆盖注明宿主和合成入口，不代表38项公告完整验收。角色／表情／站位／皮肤 Tab、剩余场景创建路径、链接类别、Stable及其他Beta、未列出的功能仍未覆盖；Agent 模型任务另按实际版本记录。

### 最小历史方法：先从官方模板初始化

保留向导生成的默认扩展类、装饰器、清单身份和导出；在该类中添加以下方法，再按模板安装依赖、构建并在 Studio 刷新。不要复制整份类覆盖已有扩展，不把方法自动调用放进渲染或注册钩子。

```typescript
static historyProbe = this.method({
  id: "history-probe",
  title: "历史追加探针",
  run(ctx) {
    ctx.history.append({ text: "HIST_SINGLE" });
    ctx.history.appendBatch([{ text: "HIST_A" }, { text: "HIST_B" }]);
  },
});
```

在一段旁白里选文字 → 超链接 → 调用扩展方法 → 选择实际注册的历史追加探针，参数用 `{}`。原生保存的行内内容形如 `[link=<百分号编码的动作对象>]文字[/link]`；动作对象使用实际扩展／方法 ID，编码由编辑器保存，不手猜引用。点击一次应在历史中看到三条，再点一次应追加同样三条。本次只有这个零参数方法通过，跨重启需另加持久化实现。

## 2026-10-01 选择后赋值与桌面跨进程读档

继续使用 **Windows Studio 2.3.0-beta.1** 的合成隔离工程副本，保留首轮工程与原导出。以下补验独立于上面的首轮结果，不把旧测试重新累计。

| 项目 | 原生保存依据与实际结果 | 适用范围 |
| --- | --- | --- |
| 自定义数值变量 | 原生“新建项目变量”创建 `BETA_SCORE`，数值、默认0、当前存档；未启用每次启动重置。`project.variables.json` 中 `type: number`、`kind: project`、`persistence: slot` | 仅此配置；不推断 shared／session、其他类型或启动重置 |
| 选择后赋值 | 在选项面板切到“变量操作”，选择 `BETA_SCORE`、等号、字面量42。原生保存 `mode: vars` 和 `varOps`；调试与新构建的桌面玩家真实点击后均显示 `ASSIGN_RESULT_42` | 文案 `{游玩天数}` 替换与选择后赋值分别确认；这不是自动生成所有表达式的规范 |
| 模式切换 | 原选项从“跳转片段”切到“变量操作”后，保存形式以 `varOps` 替换 `fragmentId`；后续旁白在同一 main 中执行 | 此原生面板的两种模式互斥；不能据此写成单一选项同时赋值并调用片段 |
| 桌面重启快读 | 在赋值后快存，正常退出并核对全部测试玩家进程退出；重开回到开场，再快读 | 恢复目标旁白、变量42及双图层场景；一个快存档 |
| 桌面重启槽位读档 | 另存空槽位1，再次正常退出全部玩家进程并重开，从原生读档界面读取槽位1 | 恢复相同旁白、变量42及场景；一个普通槽位，没有覆盖既有真实存档 |
| 追加历史限制 | 保存前方法的一次点击追加三条 SINGLE／A／B；两次重启读档均未恢复这三条。可见三条自然剧情历史，历史界面并非完全空白 | 与配套SDK“不自动持久化”声明一致；要保留追加记录须另做扩展保存／恢复验收，不能称本轮已实现 |
