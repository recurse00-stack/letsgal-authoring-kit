# 恢复、Git 与协作入口

## 选择覆盖本次改动的保护

工程落盘前至少有一种实际可用的恢复方式：原生项目历史／检查点、明确支持该操作的撤销、Git 或核验过的文件备份。优先已有原生能力，不强制安装 Git；“已保存”或“历史已开启”不证明原文已有快照。

按一个可审查批次保全原文，已有有效恢复点可复用，不为每个字重复备份。MCP 可用 `history_checkpoint`，支持的操作保留 opId；定稿记录恢复标识。项目历史与素材文件分别核覆盖，图片、音频、独立源码及未收录文件需另补保护。独立 Skill／插件发行仍执行所属工程约定，不要求创作者使用维护者的保护脚本。

恢复前先核影响并保全最新编辑，优先小范围；`history_undo` 的 dryRun／冲突处理见[MCP 流程](mcp-workflow.md)。[时光机](https://docs.avg-engine.com/manual/overview/backup)整工程恢复可能移除备份之后新增文件，不能当普通撤销。保护不足先补保护或交付草稿；恢复能力不授予改写或上传权限。[项目历史](https://docs.avg-engine.com/manual/overview/history)


## 限定恢复与读回

撤销自己的操作先用 `history_undo` dryRun 核 opId 和受影响对象。遇到 `UNDO_CONFLICT`，重读并只向前修复仍获准的差异，保留后来编辑。撤销返回的新操作 ID 与 undone 指向的旧操作不同；成功提示后仍核原对象、ID、字段和引用。

文件历史恢复先审阅 filesToWrite 和 filesToDelete。快照中不存在的临时配置可能需要删除才算恢复原状态；只恢复本次目标文件，不为恢复一项设置回滚整工程。恢复后重读实际生效值，不能仅看返回成功。数据行撤销的已知缺口见[数据表](ui-and-data.md#数据表的编辑与运行)。

## 多人协作

实时房间、多个 Agent 分工和 Git 合并分别处理。进入已获准的多人房间后，先按[附加包启停](customization.md#附加包的启用与暂停)核个人设置与索引；仅在已启用且适用当前宿主时加载 `letsgal-collaboration`。它负责本人范围、共享对象影响、成员占用及同步；暂停时不自动恢复，通用演出／UI／调试仍由母包维护。

附加包未安装、暂停或不适用时保持最小边界：核本人及获准章节，不把选中项当归属；重读后局部编辑，保留他人新内容；CHAPTER_LOCKED 按 details.reason 区分行占用、对齐和具体操作限制，不抢占或换磁盘绕过。本地同步正常不证明远端收到。

协作开放资格以当前账号和官方入口为准，不能从 enabled=false 或在线人数推断。测试功能不自动授权创建云端空间／上传作品。额外代理只有在用户或工程明确要求并允许时才启动。

## 项目选择 Git 时

只检查目标仓库根、分支、暂存和工作区差异，保留 HEAD、索引及原工作。只读检查优先 `git --no-optional-locks`，避免为检查刷新索引。不开跨作品父目录大库，不为干净状态使用 reset --hard、clean -fdx 或覆盖式 restore。

提交须有当前授权并沿项目约定，只纳入本次审阅范围。同文件部分暂存时，`git commit --only` 取工作区内容，不等于只提交已审阅的暂存片段；不擅自 stash／unstage 他人工作、推送或改写公共历史。JSON 冲突按结构合并，保留双方内容与 ID，不能整份选 ours／theirs 就称解决。

worktree 不自动包含未提交内容，也不备份素材；LFS、忽略和发行策略沿现有约定。安装备份可能含特调，不提交整个备份目录。恢复先将旧内容取到独立位置比较，再核 `git restore` 对工作区／索引的实际影响。[commit](https://git-scm.com/docs/git-commit) · [restore](https://git-scm.com/docs/git-restore)
