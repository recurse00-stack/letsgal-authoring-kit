# MCP 连接恢复与建连告警

工具缺席、调用失败或建连告警时读取；素材占用见[精确清理](asset-cleanup.md)。

## 插件表现与能力差异

涉及已有插件时先读[匹配版本的指南](plugin-skills.md#使用与版本选择)，再核真实启用状态、声明与返回。只有目标版本承诺的行为与实际不符才记为缺陷；未支持功能、未声明字段、正常权限拒绝和本次参数错误分别说明。设置、调度及文件会话按[任务入口](../SKILL.md#按当前任务读取)进入对应流程，不把旧版本现场直接归到当前版本。

## 工具消失或断连

1. **定向发现并调用。** 查当前客户端的 LetsGal 状态工具与服务器注册；核宿主、服务开关及实际地址。找到工具就调用 studio_get_status，核工程 ID，必要时读取目标对象。成功立即继续任务。
2. **失败后尝试一轮单服务器重连。** 定向查客户端正式提供的刷新／重连接口，区分尚未找到、确实没有、存在但影响其他工作。核共享影响后执行可用的单项重连，保留端点、授权及其他服务器；只有整应用重启或影响未明时，说明限制并协调时机。
3. **在当前 AI 会话验证。** 重新发现并调用原生状态工具，核工程、版本、权限和待处理项。写入结果未知时读回目标／agent-ops；可重试的原请求沿用 opId。
4. **仍失败就结束恢复循环。** 说明失败步骤和已尝试动作，询问是否允许 Computer Use 托底；同任务仍有效的明确许可可复用。其余分析与草稿继续。

SESSION_PENDING_APPROVAL、只读、关闭工具组、许可缺失及拒绝按[MCP 确认](mcp-workflow.md#宿主确认)处理，保留权限边界。

### 已确认值得排查的 localhost 代理问题

只有“继承代理失败、直连成功”的对照成立时才查 loopback 例外。具备网络修改授权后，可为 127.0.0.1、localhost 补直连例外，保留代理服务器和既有例外；已配置则继续查其他原因。

修改前记原值，写后读回并验证当前客户端原生工具。无效且配置仍等于本次写入值时才恢复，保留后来修改；缺授权则说明差异并请求批准。

## 建连时大量 bad-path

先调用状态及对象读取；调用正常就继续任务。需要定位时记录时间、方法、去查询参数的路径、状态、请求／会话关联号和版本，排除令牌、Cookie 及完整请求体。Windows 日志位于 `%APPDATA%/letsgal-studio/logs`；仅有 bad-path 标签时继续找请求路径证据。

同版 Codex 隔离探测曾访问 /.well-known/oauth-protected-resource/mcp、/.well-known/oauth-authorization-server/mcp，服务可对未实现路径返回 404。按实际 URL 区分元数据探测和 /mcp 工具失败。

可控的状态查询同时指定聊天与服务器以复用连接；无聊天查询可能新建临时发现连接。遇到大量连接时核查询来源、真实调用量和持续采样，再评估开销。客户端实现超出任务范围时保留诊断结果，宿主拦截与认证维持原设置。
