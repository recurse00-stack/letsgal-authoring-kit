# MCP 连接恢复与建连告警

仅在工具缺席、真实调用失败或建连告警时读取；文件占用与延迟删除另见[素材清理](asset-cleanup.md)。本页不提供宿主补丁。

## 工具消失或断连

按“定向发现 → 真实调用；成功即继续任务，失败才有限重连 → 再验证 → 失败说明与 Computer Use 询问”推进：

1. **区分工具未载入与服务故障。** 使用当前客户端提供的定向工具搜索／发现，查 LetsGal Studio 的状态工具与服务器注册；不要只因首次列表为空就认定没有 MCP。核宿主是否运行、服务是否启用、实际地址是否与客户端一致；地址和端口取现场，不硬编码。不要无限刷新全局列表。发现状态工具后先调用并核目标工程，必要时读取一个相关对象；成功立即结束恢复，不为日志告警重连。
2. **真实调用仍失败时，尝试一轮可用的单服务器重连。** 先定向查当前客户端正式暴露的能力，区分尚未发现、确认没有和存在但不宜执行；不能凭空假设按钮或接口。使用已核实的 LetsGal 连接刷新／重连接口，保留端点、授权和其他服务器。先核该动作是否会中断共享此连接的进行中任务；会中断或影响无法确认时，保留现状并协调合适时机，不猜作安全。若只有重启整个客户端／Studio 的按钮，或没有单项接口，如实说明这一步无法安全执行，不冒充成功、不强杀应用、不重建所有 MCP。无需为普通定向发现或不影响其他任务的重连逐步重复请求许可。
3. **核恢复结果。** 重新发现工具，调用 `studio_get_status`，核工程 ID、完整版本、权限与待处理状态；必要时读取一个相关对象。端口可达、HTTP 握手或独立脚本列出工具均不代表当前 AI 会话已经恢复。已有写入结果不明时先读回目标／agent-ops，不直接重发；可重试的同一请求沿用 opId。
4. **仍失败就停止循环并报告。** 说明哪一步失败、已尝试什么、哪些工作仍能继续，询问“是否允许改用 Computer Use 操作 Studio 完成本次任务？”用户明确同意前不启动该托底操作；可继续不依赖 MCP 的分析与草稿。已有明确许可仅在相同任务、范围仍有效时复用，不能由“缺工具”或一般创作委托推定。

`SESSION_PENDING_APPROVAL`、只读、关闭工具组、许可缺失和明确拒绝按[MCP 权限与确认](mcp-workflow.md)处理，不当作断线反复重连，也不通过 Computer Use 或磁盘写入绕过。Computer Use 同意只授权任务范围内的界面操作，不授权修改宿主安全设置。

### 已确认值得排查的 localhost 代理问题

Windows HTTP 代理未对 loopback 放行，可能导致继承代理的客户端失败、直接连接却成功。只在这种对照实际成立时检查代理例外；单凭 `127.0.0.1` 地址不能认定一定直连。

最小修复候选是为 `127.0.0.1`、`localhost` 添加直连例外，保留原代理服务器和所有既有例外。系统网络修改须符合当前授权及项目规则；没有授权时说明差异并请求批准，不能关闭全局代理、切换出口或改 VPS 链路。修改前保存原值，写后读回并验证当前客户端原生工具；无效时仅在值仍等于本次写入结果的条件下恢复，避免覆盖后来网络修改。原来已设置例外时不反复写入。

## 建连时大量 bad-path

“请求路径不对”不一定表示正式 `/mcp` 工具地址错误。若当前原生状态与读取成功，不因红色日志单独重连。

- 同版 Codex 的隔离探测曾请求 `/.well-known/oauth-protected-resource/mcp`、`/.well-known/oauth-authorization-server/mcp` 等 OAuth 元数据地址。不支持这些地址的服务可能返回 404；本证据不能逐条替代 Studio 的历史请求 URL。
- Codex 官方接口支持同时指定聊天与服务器来复用连接；无聊天的状态查询实现可能创建临时连接。能控制该查询时优先复用，避免反复全局发现；不能控制客户端内部行为时不声称已经修复。
- “已连接、工具调用 0 次”可能是工具发现连接，不等于泄漏，也不等于真实工具故障。少量探测通常开销低，但不能据一次短采样保证峰值与长期性能。
- 必要日志只记录时间、方法、无查询参数的路径、状态、请求／会话关联号和版本，不记录令牌、Cookie 或完整请求体。Windows 宿主日志入口为 `%APPDATA%/letsgal-studio/logs`；只写 `bad-path` 的活动日志不能反推出具体 URL。

宿主可对正常元数据探测单独分类，客户端可缓存发现结果／复用连接；这属于各自实现改进。不要靠关闭拦截、放宽权限、伪造认证头或修改正在运行的安装包消除告警。
