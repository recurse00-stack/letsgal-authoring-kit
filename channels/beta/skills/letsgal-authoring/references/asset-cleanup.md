# 临时素材、文件占用与清理

仅在创建需收尾的临时文件、撤销／删除失败时读取。先形成可追溯清单，再在合适时机保存关闭、对照处理并核实收尾；不自动定时删除，也不从过去诊断推定今天的删除授权。

## 撤销删除失败与文件占用

`INTERNAL`、`EPERM`、`EBUSY` 不表示完全未执行，EPERM 也不单独证明 ACL 错误。先读回原 ID、素材登记、实际文件和可用操作历史，区分已完成、剩余和未知；读取操作历史时区分原操作、撤销新标识及其对应关系。不整批重放 undo。

Windows / Studio **2.8.0-beta.1** 的 GIF／WebP 现场有 Studio 持有文件的证据，同版 Sharp／libvips 的独立实验复现文件缓存占用。关闭缓存或受大小／并发限制的 Buffer 输入仅在库级验证；宿主隔离目录 EPERM 未完整复现。APNG 的有限样本未复现，不保证换格式能解决。其他版本核现场，不当作已知必现缺陷。

运行中登记准确路径、错误和操作 ID，必要时只读查占用。暂留小测试素材时核当前引用、是否孤立和是否进入打包；没有可用接口时不能填成“无引用”。不强关其他进程句柄、改 ACL、无界 force 删除或修改宿主缓存库／EXE。rescan／缩略图重建没有已验证的解锁作用。

## 记录真实对象

创建时在任务的持久记录中填[最小清单](../templates/TEMP-CLEANUP.example.md)，不只留聊天承诺。登记工程、用途和证据来源、实际路径、创建前是否存在、文件哈希、可取得的素材 ID／opId、引用及打包状态、处置与恢复位置；包括本轮素材、inbox 输入、临时脚本／导出和可证明归属的失败残留。

导入可能复用旧文件，不能把请求名／folder 当实际落点或新建证据；原有复用项保留。漏记旧任务时，凭原调用结果、操作历史及现存文件补录，注明历史证据与当前检查时间。缺路径、来源或身份等关键证据时写 UNKNOWN 并暂留；不能只凭文件名、后缀、时间或当前未引用推定归属。

## 保存关闭后逐项处理

1. 审阅本次精确名单，核最新引用、文件与采用状态；作品成品、后来采用的内容、原有资源和必要恢复资料不算垃圾。待删独有内容先保全并核哈希，已有合格恢复副本可复用。
2. 等共享宿主的工作可中断，重新确认工程和可关闭时机，再正常保存关闭目标工程；核其他实例与实际占用已释放，不以窗口消失为准，不强制停止其他工作。已有授权不逐文件重复问删除许可，范围或共享影响变化才协调。
3. 规范化绝对路径并核准许目录边界和重解析路径，逐项对比来源、哈希、关闭前最新引用。只删清单中合格项；变化、新引用、归属不明或证据不足则暂留。已不存在记为确认已不存在，不重复撤销。
4. 失败隔离记录只有对应关系、格式与恢复用途均清楚时才处理。未知就保留待核，不按日期、后缀或整个 `.studio`／quarantine 目录清空；不能虚构通用隔离目录清理合同。
5. 逐项读回文件，剩余项对照清单；仅在已有证据指向的本任务输出目录检查漏记文件，先补证再处理。需核工程登记／引用时，在合适时机通过获准官方入口检查；磁盘不存在不证明工程状态一致。

## 完成与暂留

明确终态为“已删除并核验”“确认已不存在并核验”“确定保留（如原有复用／成品）”；“等待关闭”“证据不足”“处理失败”是待处理状态，不能算完成。文件层与工程登记层分别记录；后者尚未核实就说明收尾缺口。

全部应处理项完成必要读回后，保留精简结果、精确处置清单和必要恢复入口，清除已核实无用途的脚本、暂存和重复记录。副本只有不再承担恢复用途、或已有另一份核验过的等效恢复材料时才可清理；不删唯一恢复副本。未完成项保留唯一可续办清单，不能为消除残留抹掉证据。

正常退出通常释放进程句柄，但此前现场尚未完成真实宿主退出后清理验收；本流程不是引擎已修复的声明。
