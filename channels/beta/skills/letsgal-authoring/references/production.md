# 创作协作与制作

先确定本次要改变的阅读体验、玩家动作和反馈；执行方式由 Skill 入口选择。纯讨论和草稿不要求进入工程读写流程。

## 与创作者协作

沿用已确认设定、角色声线、叙述视角和作品目标；只读保持连贯性所需的原文，不孤立改句，也不默认载入整部作品。讨论提出少量有明确区别的方案，说明具体效果与取舍；临时设定标明待定，不靠堆候选把筛选工作推给创作者。

明确委托后主动完成授权范围内的整合稿，不逐句索要批准。主角动机、关键转折、结局等歧义会改变结果时集中询问；小的实现选择自行处理。部分采用只整合明确选中的部分；“更冷淡”等语气调整不自动改变动机或剧情方向。保留、替换和待定由反馈判断，不要求创作者填写固定表格。

采用且获准落盘的结论写回原有正式内容，不另建第二套设定库。已有／已采用／定稿与当前草稿的改删边界见[内容保护](safety.md)。交付完整修改结果或清楚的差异，避免让创作者重新拼接。

## 制作层次与完成条件

新工程优先由 Studio 生成骨架；不能操作编辑器时交付独立内容及导入步骤，不猜写完整 project.json。文字草稿、章节数据与可运行游戏分别交付。

| 任务 | 需要的信息 | 完成时核对 |
| --- | --- | --- |
| 讨论／改写 | 相关原文、目标、已确认设定 | 声线、事实、采用范围与无关改写 |
| 局部对白 | 目标及邻近上下文、原始内联内容 | 目标文字、样式、ID和非目标参数 |
| 同目标批量修改 | 精确范围、命中项和干扰项 | 实际命中范围及读回差异 |
| 分支／变量 | 进入条件、初值、动作、反馈、回流 | 引用、真实变量变化、受影响路线 |
| 跨章／蓝图 | 真实入口、调度模式、章索引 | 候选、条件、无候选和终点 |
| 持久数据 | 读写者、保留策略、旧存档影响 | 按任务另查保存读取及全新启动 |

章内调用结束会回到调用处，避免重复奖励；endChapter 不等于整个作品结束。蓝图只用于已启用的工程，画布位置不是执行顺序；前处理章节不加入普通章顺序或候选池。具体规则见[章节调度](https://docs.avg-engine.com/advanced/chapter-scheduling)。

## 变量、素材与最小案例

从工程读取真实 key、类型、默认值和消费者。“当前存档／跨存档”与“每次启动重置”分别判断，启动重置不是第三种持久范围，也不同于扩展 session。增量修改与直接赋值必须按用户意图区分；固定写“得到42”的台词不能证明变量变为42，应看运行数据或插值反馈。[变量说明](https://docs.avg-engine.com/advanced/variables)

需要在后续位置重新判断时编排独立判断点，不把同一 If 当作持续监听；适用证据见[当前能力](current-capabilities.md)。素材缺失先定位引用和许可，获准时使用可识别占位，不静默换空白图。普通表情、姿势、部位与皮肤引用不能混用。

[选择练习](../examples/选择练习.json)包含两项选择、各自结果和返回主线。加入工程时用当前执行方式创建结构、取得有效 ID并登记既有索引；保持原入口。它是合成章节，不是完整作品或通用运行保证。

## 交付

文字质量与工程正确性分别判断。改字读回即可核对的范围，不自动扩大到全工程、玩家、存档或导出；路线改变才检查相关路线，持久数据改变才增加保存读取。预览入口、继承前文、完整调试和导出玩家各自说明。复用仍适用的证据，不沿用旧结果虚报本次完成。

达到本次目标、读回差异且必要问题已说明就交付。说明实际变化、验证层次、未决项与恢复入口；导出、外部发布和额外服务调用不随普通创作自动发生。
