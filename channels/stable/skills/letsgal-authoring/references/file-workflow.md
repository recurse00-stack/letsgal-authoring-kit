# 正式版执行流程

适用2.5.0。讨论和草稿直接协作，不因缺少Studio控制工具而停止。执行作品改动时先确认工程、授权范围和恢复保护；不要求MCP，不套用Beta协议。

## 选择操作方式

- 活动工程：优先当前可用且已授权的Computer Use／原生界面，确认窗口、工程、焦点和编辑权；同范围不反复确认点击，不抢占用户正在输入的界面。
- 直接改磁盘：先正常保存并关闭目标工程，确认无其他实例持有，再作局部编辑。等待自动保存不等于关闭；不能确认时只准备草稿／补丁，不强制结束进程。
- 独立扩展源码、Skill与发行材料：沿所属工程文件与构建流程，不要求关闭无关Studio工程。

只有工具或权限不足时说明具体缺项；只读或明确拒绝不能换工具绕过。新工程由Studio生成骨架，缺界面工具就给具体人工入口，不捏造初始化结果。

## 定位、修改、读回

已知文件／对象直接精读目标及邻近上下文，名字不唯一时限定章和片段；各章都可能有main。需要变量／素材才读取相关定义，不先遍历全工程。写前记录原文及哈希／修改状态，写入前变化则重读合并。

局部改字在原对象中修改目标文本，保留内联格式、ID、未知字段与其他参数，具体磁盘结构见[JSON](json.md)。同目标批量替换先列匹配范围，排除同名变量、路径及其他角色。结构改动只更新相关引用和既有索引，不重建整章来修改一句话。

写后读回实际文件及差异。检查只覆盖改动涉及的结构；需要原生加载、分支路线或持久状态时明确下一层验证，不把文件成功等同于运行成功。目标完成后停止扩大范围。

结果不明先查实际内容，不反复重写；检测到后来编辑先合并。恢复遵循[恢复保护](collaboration-git.md)，小范围恢复且保留后续内容。无法确认完成就记录未决项。
