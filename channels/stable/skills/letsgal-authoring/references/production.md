# 从制作目标到可玩片段

正式版使用已获准的原生界面，或在正常保存并关闭工程后处理文件。先核[至少一种有效保护](collaboration-git.md)，再按本次目标读取、制作和验证；本载荷不要求MCP接入。

先确定玩家本次会看到什么、做什么、得到什么反馈及何时结束。新作的主角、结论或玩法核心仍需用户决定；不影响方向的占位可标明为临时。已有作品沿用设定、声线、稳定 ID 和现有入口，旧原型不自动成为正文。

## 与创作者协作

用户此前完成或已采用／定稿的内容，未经明确范围授权不改删；AI 当前受托新作的未定稿草稿可在委托范围内迭代，一经采用就按正式内容保护，与作者身份无关。工程落盘须有[至少一种有效保护](collaboration-git.md)，具体状态判断见[安全操作](safety.md)。

讨论、候选草稿、正式采用和工程写入分别判断。已有明确委托时主动完成可审阅稿和授权范围内的实施，不逐句索要批准；仅讨论时不写工程。主角、关键转折、结局或玩法核心未确定且会影响结果时，集中询问；明确委托自行设计时可以给出提案，不假装已成为设定。

读相关上下文以保留人物声线、叙述视角和已确认事实；需要多少原文由连贯性决定，不为省字只读孤立一句，也不无故加载整部作品。少量有明确区别的方案应说明效果与取舍；不堆相似候选把筛选工作推给创作者。临时占位／假设保持可识别，采用且获准落盘后回写原有正式内容，不另造第二套设定库。

理解反馈中哪些要保留、哪些替换、哪些仍未决定，不要求创作者填写固定表格。只采用方案的一部分时，仅整合明确采用的内容，不顺带把该方案的临时设定写成事实；“更冷淡”等局部语气反馈也不自动改变人物动机或剧情走向。重要指代会改变结果时集中询问，已有授权且范围明确就直接修订所属原文，交付整合稿或清楚的差异，不让创作者自行拼接。

交付围绕实际变化和仍需选择的事项，不复述全套规则。文字审阅看目标、声线、事实和无关改写；工程校验另看引用和运行，两者不能互相代替。

## 选正确的制作层次

新工程优先由 Studio 生成骨架；无法控制编辑器时完成独立内容并说明导入步骤，不凭猜测拼完整 project.json。文字草稿、导入文本、章节源 JSON 和可运行工程分别交付。纯 Skill 不提供任何模型或控制能力。

| 当前层次 | 制作与观察 |
| --- | --- |
| 章内线性片段 | 编排 Block、选项和结果；调用片段结束后回到调用处，检查是否重复发放奖励 |
| 基础跨章调度 | 核对章索引、入口和停用状态；正文结束／endChapter 不等同于整个作品已结束 |
| 蓝图调度 | 仅用于实际启用该模式的工程；核对入口、候选、条件、空候选和终点，画布位置不是执行顺序 |
| 前处理章节 | 在目标调度资料中核对用途，不加入普通章顺序或候选池，不用普通剧情示例覆盖其结构 |

蓝图及相关新变量功能有 v2.0.0 官方版本说明，旧版不默认套用。[章节调度](https://docs.avg-engine.com/advanced/chapter-scheduling)与[版本选择](version-compatibility.md)

## 变量和素材

从当前工程取得变量 key、类型、默认值、读写者和保留策略。项目变量的“当前存档／跨存档”与“每次启动重置”分开设置；启动重置不是第三种范围。读档、回标题、返回入口、局部预览重载和全新启动不能互相代替。项目启动重置也不等同于扩展 save schema 的 session。[官方变量说明](https://docs.avg-engine.com/advanced/variables)

需要状态改变时先列初值、触发动作与期望值，在运行数据查看器或变量插值正文中观察；固定写“得到42”的台词不能证明真实值已变。更改 key 或含义需查扩展中的字符串消费者和旧存档影响；不能从 UI 显示推断已经落盘。

需要后续重新检查状态时，用独立判断点表达，先验证实际路径。2.5.0样例中值由0改为1后，同一片段内的If再次调用仍沿用真分支；独立If选择假分支。不要用同一If反复调用承诺动态求值，也不批量改已有ID。详情和实际入口范围见[JSON工作法](json.md)。

核对实际角色、场景、表情／皮肤、素材和授权。缺资产就报告缺项，获准时用可识别占位，不静默替换为空白图。姿势／部位与普通表情的引用结构不能混用，写入前取目标正式版保存样本。

## 一个完整的小案例

[选择练习](../examples/选择练习.json)用两项选择进入两个非main片段，显示结果后返回主线。由原生界面建立结构，或关闭工程后生成独立ID并更新相关引用、既有章索引；保持原入口。先静态查引用，再从实际入口各走一条路线，应看到对应结果与回流。本文件是合成练习，不能当作任何工程的运行保证。

复杂片段仍围绕进入条件、动作、反馈、离开条件制作。把角色心理描述与游戏状态区分；条件边界、无资源／无候选、重复进入和失败分支需要可观察结果。

## 验证与交付

对白改字读回文本、ID、行内样式与非目标字段；无需因此重跑玩家或存档。分支与状态变化再看受影响路线，持久数据才增加存读档。只运行与本次改动相关的验证，复用仍适用的结果并标明版本。文件差异与静态检查 → 当前宿主局部预览／完整调试 → 保存读取及全新启动 → 请求的导出平台，各自记录。实时预览随当前片段和选中区块更新；运行按钮可固定不同方式，按其菜单核对“调试运行”“从当前章节调试”或模拟游玩，不能因选中片段就假定完整调试从该片段开始。2.5.0本机默认调试从作品入口开始，片段预览另验。涉及启动行为时最终用导出游戏验证，不能用刷新预览冒充关闭后重新启动。

素材许可、私人信息和秘密检查针对实际候选包。导出和外部发布按当前任务授权执行，不随更新 Skill 自动发生。交付说明修改文件、玩家行为、实际通过范围、剩余缺口与恢复入口。

2.5.0正式版的继承前文预览、六类剧本导出、角色／界面和统计工作见[Stable 2.5](versions/stable-2.5.md)。界面名称与公告用词分别核对；局部预览、前文状态重建、真实入口与导出玩家分别判断。预览默认选择的前文路线可能不同于玩家手选路线，先核默认选项再比较。
