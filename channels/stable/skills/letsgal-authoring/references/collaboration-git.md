# 协作与恢复保护

## 至少一种有效保护

工程落盘前确认一种实际可用、覆盖本次改动的恢复方式：原生项目历史／检查点、支持本次操作的撤销、Git或核验过的文件备份。优先已有原生能力，不强制安装Git；“已保存”“已开启历史”不证明原文已受保护。

- 有效原文快照可复用；缺失时按一个可审阅批次建立保护，定稿保留恢复标识，不为每个字重复备份。
- 项目历史与素材文件的覆盖分别核对；图片、音频、独立源码及未收录文件需补足保护，不能以剧情检查点保证素材恢复。
- 操作撤销须由当前工具明确支持，保留操作标识，恢复前核影响和冲突。恢复优先小范围，先保全最新状态及后续编辑；有Studio确认要求时遵守。
- 保护不足先交付草稿或补丁。恢复能力不授予修改权限，不因保护自动同步上传。

[项目历史](https://docs.avg-engine.com/manual/overview/history)、[时光机](https://docs.avg-engine.com/manual/overview/backup)和[版本管理](https://docs.avg-engine.com/manual/overview/version-control)覆盖不同范围。时光机整项目恢复可能覆盖当前内容并移除备份之后新增文件；先看范围，不能当普通撤销。

独立插件源码、Skill与发行材料继续执行所属项目的保护要求；公版不要求所有创作者使用维护者的Git保护脚本。

## 多人协作

如另有多人协作附加包，先按[附加包启停](customization.md#附加包的启用与暂停)核启用状态与宿主范围。暂停时跳过加载，不因进入相关任务、安装或升级自动恢复。仅适配其他通道的附加包不能套用于本通道 2.5.0；仍可按本页保留协作与内容边界。

明确对象、目标与不动范围；同一文件直接编辑由一个写入者整合，结构化工具按其revision与编辑权协调。并行草稿不能绕过冲突控制。只在用户和环境允许时启动额外代理，不因Skill存在额外开模型会话。

协作是否可用及账号资格，以目标版本、当前账号和官方入口为准，不从历史内测公告推定当前开放状态。保留Studio当前版本的章节／逐句编辑权与未同步内容。云端覆盖可能丢弃本机改动，先保全并核具体授权；外部文件操作不能假定遵守编辑器的协作锁。[协作说明](https://docs.avg-engine.com/manual/overview/collaboration)

## 选择Git时

仅在项目采用 Git 且本次需要相关操作时，读[Git 工作流](git-workflow.md)。

## 交接

复用已有简短状态文件，记录实际目标、已采用决定、修改范围、验证层次、未决项、恢复标识及仍运行的进程。详细过程另存，不把整个历史变成下次必读入口。
