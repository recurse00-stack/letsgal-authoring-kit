1. 入门、安装与确认 AI 实际读取

LetsGal Authoring Kit 是给 AI 使用的创作指南，帮助它选择接口、保留已有内容并检查结果。它不包含 LetsGal Studio、AI 模型或 MCP 服务。你仍在自己的 AI 工具中提出需求，在 Studio 中查看作品。

准备什么

准备完整解压的本包、能够访问本地文件的 AI 工具，以及作品的备份。只讨论故事可以暂不连接 Studio；实际修改工程还需确认版本、工程与 MCP。Windows 安装器使用 PowerShell 5.1 或 7，无需管理员、Python 或 Node；可选检查脚本才需要 Python 3.9+。

本包版本为 0.2.9 / 20261111-stable300。Stable 对应 Studio 3.0.0，Beta 对应 2.9.0-beta.1／2.8.0-beta.1。Skill 版本与引擎版本是两套编号。完整安装包从 GitHub Release 附件取得。

安装一次

  1. 在完整解压目录双击 Install.cmd，不要在压缩包内运行，也不要单独摘出脚本。
  2. 选择工程对应的正式版或 Beta，再选实际使用的 Agent。通常选“个人 · 所有项目”；只给一个作品使用时选“项目 · 仅此工程”。
  3. 核对最终目录、所选／已装通道、版本与修订，再导入。目录应为 AI 实际发现 Skill 的位置，不能选 Studio 的程序文件夹。
  4. 展开“更多选项”，点击“检查安装”。底部状态栏应显示“检查安装 · 校验通过”，结果框显示“安装文件校验通过”。
  5. 打开 AI 的新会话，进行下面的读取核对。文件校验通过只证明文件完整。

安装器仅替换所选 Skill，保留个人偏好、插件资料和旧版备份，不安装或升级引擎。两个位置已有同名 Skill 时先确认实际加载来源；不要随手复制第三份或删除未知副本。

怎样确认 AI 真的读了

可以直接发送：

请使用 letsgal-authoring，实际读取你发现的 SKILL.md，告诉我加载路径、版本、修订和通道。读取已有的个人偏好，并说明本次任务会用到哪些约定。先只核对，不改工程。

预期得到具体来源及匹配的 metadata，而非“我会使用这个技能”。继续给出一个局部改句任务时，AI 应读取目标原文及相关专题。插件资料的核对见个人偏好与插件指南。不需要让 AI 每次把整份 Skill 或私人文件复述出来。

如果只有安装成功消息、旧会话仍回答旧修订，先新开会话并核实际路径。若新会话也找不到，查Agent 目录说明，确认该客户端支持本地 Skill、所在环境和发现配置。粘贴指南文字不会赋予文件权限或 Studio 控制能力。

首次需求怎样写

在“序章”的“车站”片段里，只把售票员第二句改得更简短。先读前后文，保留样式、行 ID 和配音绑定；给我改动前后对照。其他句子不改。

先给工程、位置、目标和边界，AI 可以在授权范围内完成读取、修改与必要检查。尚未决定写入时说“先讨论／先给候选”。已有内容和采用的定稿继续受保护；新写且未定稿的受托草稿可按目标迭代。作品备份独立于安装器的 Skill 备份，见恢复。

2. Stable／Beta、工程身份与 MCP

准备什么

确认目标作品、运行中的 Studio 完整版本和已安装 Skill 通道。保留 -beta.1 等后缀。作品自己填写的版本号不一定是引擎版本，不能拿它替代“关于”或运行实例的版本。

目标 Studio 选择的载荷 资料范围
3.0.0 Stable 当前正式版 MCP 工作流
2.9.0-beta.1 Beta 嵌套剧情等 2.9 指导
2.8.0-beta.1 Beta 保留明确标注的 2.8 路线
2.5.0 历史发行 使用当时的完整资料与包
其他／不明／来源冲突 暂停工程执行并核身份 版本差异需本次明确许可；可继续讨论和只读核对

开工检查只在首次工程操作时静默进行，同一实例和任务复用；发现升级、热更、重连或接口差异时才重新核对。不会每轮对话联网查更新，纯讨论不触发。

实际主版本、界面热修复与更新偏好分别核对：3.0.0 + 3.0.0-stable-r2 可以同时选 Beta 更新通道，此时仍使用 Stable Skill。当前 Stable 维护基线为该 r2；Beta 的旧证据未记录完整热修复身份。

不匹配或热修复未知时，AI 暂停目标工程执行，说明实际组合和维护基线，只询问一次是否允许本次任务继续；你明确同意后才按限定范围调用，后续复用许可。来源冲突或连错工程先解决身份问题。

切换 Skill 不会切换或更新引擎。同一个技能目录只安装一份同名入口；不同版本的作品可以使用各自项目范围，但要核对 AI 的发现优先级。

连接到正确工程

按官方 MCP 接入指南，在目标 Studio 窗口取得该窗口提供的真实连接地址，再配置到 AI 客户端并批准所需连接。网页中的示例地址只作格式参考。不要使用别人截图里的端口，也不要把令牌贴到公开反馈中。已配置连接时先验证，不必重复安装或重注册。

请先读取当前 Studio 状态，核对版本、工程名称和 project.id、连接权限、可用工具组及待保存状态。我这次要改的是“星港练习”。若连到别的工程，先停止写入并说明差异。

预期看到来自当前 MCP 返回的身份。多个窗口可能对应不同端点；窗口标题相同也不能代替 project.id。连接成功、获得写权限、一次具体高影响操作获批是不同状态。

切换工程与独立窗口

3.0 的 studio_open_project 可打开已有工程，会在当前窗口保存并关闭原工程，不等于新建独立窗口，也不能新建工程。需要保留原工程时，应使用目标已有窗口，或明确授权一次新窗口初始化。2.9／2.8 不套用这个 3.0 入口。

切换、重连、长时间等待确认后，AI 应重新读身份、权限和当前内容版本（revision）。旧 revision 是冲突检测依据，不能一直重复使用。

遇到差异怎么办

现象 怎样继续
等待连接批准 在目标窗口确认连接；AI 继续可做的只读资料工作
只读或明确拒绝 保持权限边界，先给草稿；不能绕到磁盘或界面强写
工具没出现 定向发现并真实调用状态工具，失败后有限尝试单服务器重连
有工具却超时，写入结果未知 先读目标和操作记录，确定是否已经落地；不要整批重发
仍无法连接 说明已尝试步骤；需要界面兜底时再按任务授权使用

没有 MCP 时仍可讨论、制作草稿或维护独立扩展源码。直接离线写工程前，需要正常保存关闭目标工程并确认其他实例已释放。Computer Use 是必要兜底，日常制作优先专用 MCP。

查阅：只读版本命令

在完整包根目录运行；不会探测、启动服务或修改工程：

python "channels/stable/skills/letsgal-authoring/scripts/inspect_version.py" --studio-version 3.0.0
python "channels/beta/skills/letsgal-authoring/scripts/inspect_version.py" --studio-version 2.9.0-beta.1

工程执行检查加 --gate --patch-id 3.0.0-stable-r2（只填写目标的实际标识）。operation_gate 的 matched 表示身份匹配，confirmation_required 表示需本次许可，identity_required 表示先查身份。--update-channel beta 只记录更新偏好；不改变实际版本判断。

可用参数还包括 --studio-exe、--project-version、--channel、--sdk；项目参数只填明确固定的目标引擎版本。reference_selected／退出码 0 表示选到资料；UNKNOWN／退出码 2 表示缺失、冲突或未登记。选到资料不代表运行兼容已验证。

3. 一次完整的剧情修改与分支练习

准备什么

使用独立练习工程或作品中的获准测试章，先确认版本、工程身份及覆盖章节的恢复点。以下新建练习面向 3.0／2.9 的嵌套选项；2.8 让 AI 按该版的 branch／结果片段结构实现相同行为，不直接复制嵌套标记。

从一句话到两个选择

先发出完整目标：

在独立练习章新建“车站选择”。先显示“列车即将出发。”，给出“问路”和“候车”两个选项。选“问路”显示“站务员指向二号站台。”，选“候车”显示“你坐到长椅上。”。两条路线结束后都回到“广播再次响起。”。不改原有章的入口和顺序，告诉我怎样从本练习开头预览。

AI 应先取正式章／片段 ID，再按当前宿主能创建的结构写入。3.0／2.9 通常把选项正文放在同一片段的嵌套菜单内；配对标记表示各路线边界，不能把两条结果顺序接在同一条路上。完整 JSON 示例分别在 Stable 样例和 Beta 样例，它们是结构参考，不能直接覆盖作品配置。

预期剧情：

列车即将出发。
  问路 → 站务员指向二号站台。
  候车 → 你坐到长椅上。
两条路线均继续：广播再次响起。

怎样核对

  1. 查看改动摘要：新增了哪个章、片段，原有入口是否保持。
  2. 确认写后从 Studio 读回，选项、两段结果和共同尾句都在；结构校验没有未处理错误。
  3. 从练习开头选“问路”，应只出现问路结果，再到共同尾句。
  4. 重新从开头选“候车”，应只出现候车结果，再到共同尾句。只走过一条路线不能算两条都通过。

选项出现但无结果时，核本版结构的目标 ID 或路线边界；两路混播时核菜单结束标记及尾句位置。先读真实结构，不通过整章重写来碰运气。

再做一次局部改字

只把“你坐到长椅上。”改成“你坐在窗边的长椅上。”。保留这行原有的颜色、粗体、ID、语音与其他字段；展示改前改后，并读回确认。

AI 应在原富文本内只改对应文字。行 ID 关联翻译或音频，不能为改一句话重建整行。旧配音绑定可以保留，但台词改变后应提示录音可能不再匹配，是否重录由本次需求决定。

加条件时怎样提出需求

在练习里用现有布尔变量 hasTicket 决定提示：true 显示“请进站”，否则显示“请先买票”。先核实变量确实存在、类型和作用域，不擅自更名或建立同名变量。

预期条件分支互斥；最终 else 没有额外条件。检查变量初值、修改位置和两条结果，而不只看代码格式。旧版 branch、if 与普通片段调用有各自的返回和跨章规则：3.0 的旧 branch 可按契约调用唯一启用的跨章片段，不能据此把普通 call 或 Beta 也改为跨章。

查阅：结构检查器

在完整包根运行（其他工作目录改用脚本绝对路径）：

python "channels/stable/skills/letsgal-authoring/scripts/check_project.py" "<章节或工程绝对路径>"
python "channels/stable/skills/letsgal-authoring/scripts/check_project.py" "<章节或工程绝对路径>" --format json-only

Beta 改为相应目录。检查器只读文件；JSON 输出与退出码说明见格式专题。退出码 0 仍需阅读 warnings；它不证明资源存在、条件意义正确或玩家路线已运行。遇到未来格式先用 json-only 核基本 JSON，再查目标宿主实际样本，不自动迁移格式。

4. 舞台、演出、多语言与配音

准备什么

准备已获准使用的角色、背景和音频，说明目标章节、效果及目标语言。先核实际资源 ID／路径；配置存在、剧情引用和实际播放是三个检查点。删除素材前还要核引用和备份。

让角色完成一段演出

在车站练习开头显示角色阿岚，先淡入，再向右平移，最后回到静止状态。已有角色布局和口型设置保持。请选用当前版本可创建的指令；完成后从这段开头连续预览，并说明检查到的效果。

AI 应读取角色布局与工程预设，把需要的配置和剧情启用连起来。普通显示／更新／移除角色、镜头控制与演出段按任务选用；旧镜头动画可以维护，不因版本更新自动迁移。

核对对象、移动方向、时长、镜头跟随和最后位置。只看时间轴跳到终点不能验证动画；有画面判断价值时再用预览捕获。后台循环必须有明确停止路径，例如离开场景时停止呼吸以外的循环段，不能让测试遗留后台动作。

口型与配音

给这三句绑定准备好的原声录音，保持其他句子的音频。先预演匹配范围，读回行与录音的对应关系，再试听这三句。缺资源时列出缺项，不用同名文件猜配。

先核语音表的映射键与台词行，预演自动匹配，避免覆盖已有录音。文字口型与音频口型依目标版本和角色配置选择；配置校验与真实听感分别确认。语音识别工具缺席先查工具组及权限，不直接推断宿主无配音能力。

多语言练习

为车站练习增加英语译文与英语配音，原文、原声和其他章节不变。保留稳定行 ID；发现源文已改时只处理受影响条目。请分别核对文字语言、配音语言、录音键以及缺失英语录音时的回退。

3.0／2.9 的译文写入按条返回结果，同批可以部分成功。AI 应保留成功项，只对 sourceHash 过期的条目重读源文并重新翻译，不能把整批重发。文字显示语言与配音语言可分别选择，Studio 自身界面语言是第三项设置。个别行的语言覆盖与语音表匹配不同；移除覆盖回到表匹配，不代表静音。

预期交付包含：改动的行、每种语言的文本／音频对应关系、实际读回和试听范围。检查切换文字、切换声音、缺失录音回退以及临时预览设置恢复。2.8 的具体能力按 Beta 对应资料选择，不套用后来新增行为。

遇到差异怎么办

看不到预览时先处理可见性和运行状态，不要反复抢前台。导入／删除报错时读回登记、文件和隔离区，区分已完成与剩余项。3.0 独立 GIF／WebP 样本的限定撤销、删除已通过。遇到新失败按本次文件与返回定位，旧版占用历史仅作版本参考。

下一步：UI、数据与扩展。AI 字段资料见所选通道的舞台、演出及剧情专题。

目标 先评估

物品／角色条目与列表展示 数据表、绑定和界面动作

一个地点牌小练习

在独立练习章显示地点牌“旧车站”，停留后关闭并继续对白。优先复用工程现有 UI 和动作；不替换标题页、菜单或主题。请告诉我打开与关闭的入口，并验证关闭后对白仍能继续。

准备目标画面、尺寸要求及可用 UI 文档。预期得到界面入口、文字来源、显示／关闭动作和局部修改。检查位置、缩放、前后遮挡、退出后的输入控制；文档保存成功不等于按钮已能点击。

若本次需要独立 UI 文档，AI 应先读目标 schema，用实际返回的元素 ID 修改。整页替换必须保全原文、稳定 ID、状态、动画和引用，不能为改标题删掉其他组件。

数据表怎样核对

在练习数据表添加一个测试物品“车票”，价格 12；先读现有字段、类型和行 ID，保留其他行。将它显示到测试列表，再核对读回与界面取值。

数据表是结构化条目，行 ID 常被界面和剧情引用。新增／改值后核字段和引用；运行副本及存档行为另验。需要删除时先有覆盖集合文件的历史恢复点。project_delete 不支持普通 undo，恢复原行按限定历史恢复处理，不能把新建同名行当作保留原 ID 的恢复。

需要开发扩展时

现有方法不能表达这段规则。请先核目标 SDK 与公开接口，给出最小实现，保持原插件 ID、源码关联和现有设置。分别报告类型／构建、Studio 加载、方法调用和存读档检查。

普通玩家界面与供作者使用的 Studio 组件分开实现。参数和预设按目标 SDK 真实类型填写；Stable 3.0 的新增字段不能直接写进 2.9／2.8。调用方法前核类型、范围、枚举与资源引用，校验通过也不能保证业务条件正确。

状态分清作者配置、单槽存档、跨档数据和本次启动状态。恢复存档时可能重新经过逻辑入口，奖励／扣款等副作用需要按 SDK 的恢复语义处理。是否在 Studio、Player、Web 或导出中测试，分别报告。

重置扩展设置前读设置 reset 差异。看到“reset 成功”不能直接宣布默认态已恢复；显式设置为默认数值也不等于恢复默认态。

6. 个人偏好、插件指南的建立与使用

三种资料放在哪里

~ 指实际运行 AI 的用户主目录；WSL、远程环境或另一账号可能是不同目录。

内容 位置与用途

公共 Skill 只包含读取机制。更新、切换或卸载主包保留用户区；不要把私人内容直接改进公共 Skill。旧根目录 user.md 仍兼容，新旧都存在时应先比较冲突，不能创建空白文件遮住旧配置。

保存一条个人偏好

请把“修改现有工程前先读当前章节摘要”保存为我的 LetsGal 偏好，保留已有内容，写后读回。这个要求只针对 LetsGal 制作。

预期只在个人区补充实际要求，并能读回原有条目与新增条目。首次执行工程或扩展操作时主 Skill 应主动读取已有偏好；纯讨论按讨论范围进行，不因此自动修改工程。

给插件建立指南

准备插件真实清单 ID、版本／修订、可靠说明或源码，以及目标 Studio 版本。不要只提供工坊显示名称或随意取一个 ID。

请分析我指定的这个插件，核实 ID、版本和适用工程，为它建立插件 Skill。写清实际方法、参数、完整调用例子、存档影响及验证范围。保留已有资料，保存后从主 Skill 的查找路径读回入口与必要引用，更新索引。不要因此安装或启用插件。

AI 可按插件写作模板整理有依据的用法。预期得到匹配版本的正文、必要引用及 plugins/INDEX.md 条目。未知参数标明待查，不能把猜测写成正式接口。

保存后的核对不止“文件存在”：应实际打开 SKILL.md，沿链接读取本任务所需引用，并确认与真实 ID／版本一致。安装运行插件与保存知识是两个动作。

平常使用时怎样确认读取

请用当前工程的这个插件完成车票规则。先核实际 ID／版本和启用状态，读取对应插件指南及本任务必要引用，再选择方法；告诉我采用了哪个版本的资料。

主 Skill 会通过索引或已确认 ID 的版本目录直接读文件，即使这个嵌套 Skill 没有出现在 AI 的全局技能列表中。无需再次注册、重复安装，也无需每次额外点名子包。

索引缺失时，AI 应定向检查已确认 ID／版本的目录。存在多个版本时以本工程实际版本为准，不自动取“最新”；版本冲突要核清，不能以升级插件来消除冲突。资料被明确暂停时保留并跳过加载；暂停协作附加包也不会因主包更新自动恢复。

如果 AI 只说“找到指南”却不知道方法细节，让它实际读正文及相对引用；若资料与真实接口不符，保留差异并按本项目已核实的清单、SDK／源码和运行证据处理。没有指南时仍可查可靠文档，不必为一次只读咨询自动建立资料库。

7. 已知差异、排错与精确恢复

写前准备与写后核对

准备至少一种实际可用、覆盖本次改动的恢复点，优先已有项目历史／检查点或支持该操作的撤销；素材、独立源码等没有覆盖的部分另做备份。安装器只备份 Skill，不备份作品。已有有效保护可以复用。

请只恢复本次试改的内容。先比较原恢复点与当前文件，列出会写回或删除的对象，保留试改之后我新增的内容；恢复后逐项读回，说明还存在的差异。

精确恢复按对象、字段或限定文件进行。整工程恢复可能移除备份后新增文件，不默认采用。若后来编辑与恢复目标重叠，先合并可确定的差异，再把仍需决定的部分说明清楚。

三类已确认差异

Studio 3.0.0 的官方 MCP 复测曾出现以下差异，相关操作先按右侧步骤保存原态并核对结果。

操作 实际遇到的差异 怎样核对与继续
扩展设置 reset 官方内置壳的 boolean、enum 改值后 reset 成功，但读回 isDefault=false 且缺 value；数组字段也有默认态标记差异 写前保存值是否存在、值与默认态。写后逐项比较。缺值不解释成 false、空字符串或默认值。显式写回旧值和恢复默认态分别报告
修改入口数量后 undo basic／linear 改入口数后变为 advanced／extension；undo 恢复数量却未完整恢复模式、策略和图 写前保存四项。撤销后逐项读回，必要时审阅限定历史恢复。把原图显式写回而策略变成 graph，不算完整还原原来的 linear
官方文件编辑会话 有效会话内的单句文件修改可能回到原文，dry-run 随后为空变更；仅启用内置壳也复现 普通修改优先专用 MCP。预期有改动却为空时停止 commit，保留拟写内容，核会话、文件、保存与编辑状态；安全结束会话后用获准专用接口重新读取并修改

设置字段未声明默认值时，缺 value 本身可能正常；上述 MCP 读回差异不证明 SDK 运行取值、界面重置按钮或 Player 都出错。文件会话切换章节后仍有复现，切章节不是已验证解决办法。不要为了恢复状态反复重载工程、覆盖整份配置或丢掉后来编辑。

AI 的详细操作规则按通道查阅：Stable 3.0 使用扩展设置、调度恢复和文件会话；Beta 2.9／2.8 使用Beta 设置、Beta 恢复和Beta 文件会话。Beta 的历史现象保留其版本条件，不把 3.0 复测直接当作 Beta 重测。

哪些情况不应直接叫缺陷

  • project_delete 明确不支持普通 undo。数据行依项目历史限定恢复，素材按隔离区恢复入口；普通 undo 未找回删除对象不构成该契约的失败。
  • 任意添加的未声明字段没有保真承诺。使用受支持的数据位置，保留格式契约内的内容。
  • 等待批准、只读、关闭工具组、不支持的目标平台，以及本次调用参数错误，分别按权限、能力和输入处理。
  • GIF／WebP 的 3.0 独立样本限定撤销与删除通过，旧占用现场不再列为 Stable 当前故障。出现新失败仍需核部分完成结果、引用、文件与隔离区。

只有目标版本承诺支持的行为与符合契约的实际调用不一致，才列为问题。遇到结果未知，先读回目标或操作历史，不能把超时当作完全没写。

预览与构建

WINDOW_HIDDEN 先核具体 reason 和预览状态。最小化、锁屏、遮挡或停在其他模块可能不满足官方渲染条件；不在前台本身不能证明隐藏。按授权恢复对应条件后再试一次，仍失败就保留未验项。窗口仍可见却被判为隐藏时，记录 reason、窗口状态和最小调用再反馈。

构建先核配置、工具链和 dry-run；桌面目标按实际 supportedSystems 选择，不从旧网页或操作系统名称推测。构建计划有效、产物生成、产物在目标系统运行分别验收。未构建过的导出不能写成已通过。

反馈问题要准备什么

提供 Skill 修订、Agent、Studio 完整版本、具体工具、最小输入、预期与实际返回、恢复状态。先排除版本不符、输入错误及本来不支持的操作；只发脱敏片段或独立样本。不要上传完整私人作品、账号、令牌或未经清理的截图。可以在仓库 Issues反馈 Skill 问题；宿主问题提交实际可复现的现象和步骤。

8. 更新、切换、卸载与备份恢复

更新或切换前准备什么

准备完整的新包，确认当前安装路径、通道、版本及修订，并备份作品与需要迁移的个人资料。同一产品版本可能有不同候选修订；“内容不同”不表示哪一份更新。未标注修订的旧包也不能凭目录日期猜先后。

用同一安装器更新

  1. 把新包完整解压到另一普通目录，运行 Install.cmd。
  2. 选择同一实际 Agent 位置和所需 Stable／Beta。核对预览中的已装与本包信息，再导入。
  3. 内容一致时应校验后保持不变；内容不同则先完整备份旧 Skill，再安装所选载荷。
  4. 检查安装，并在新会话核实际路径和修订。旧聊天不会因磁盘更新自动证明已经读了新内容。

个人偏好、插件知识和作品配置保留，主包不升级宿主、不启用暂停资料。遇到已安装文件被个人改动，先比较并把个人部分迁到用户区；只有明确选择“备份后继续”才替换，旧改动不会自动合并进新版。

备份在哪里，怎样恢复

旧 Skill 存在 skills 目录旁的 .letsgal-authoring-backups，安装结果及 *-install.json／*-uninstall.json 日志记录准确备份路径。备份不会作为第二份 Skill 自动发现。不要通过清空所有备份排错。

请找到上次安装日志指向的旧 Skill 备份，比较当前与备份的通道、修订和文件。先保全当前内容，只恢复指定 Skill，个人区和工程文件保持；恢复后校验文件及新会话读取。

恢复前保留当前新增内容，按准确目录核对后恢复；不复制到另一默认目录制造同名入口。个人区要另行备份，安装器旧 Skill 备份不包含它。备份可能有私人特调，提交 Git 或公开分享前检查内容。

卸载与换电脑

“更多选项”中的卸载或 Uninstall.cmd 会把当前 Skill 移入备份，保留用户区、作品和历史备份。卸载主包不等于卸载引擎或插件。

换电脑、账号、WSL 或远程环境时，在实际运行 AI 的环境另行安装；只按需要复制自己的偏好与插件资料，再核路径和版本。不要把完整个人区放进公共包。

查阅：手动安装与命令行

Windows 完整包根目录示例：

powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -Harness Codex -Scope User -Channel stable -NonInteractive
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -Harness Codex -Scope User -Channel stable -Action Check -NonInteractive
参数 用途
-Action Install、Check 或 Uninstall，默认 Install
-Harness Codex、Claude、Cursor、Copilot、DSH、Manual
-Scope User 或 Project；Project 配 -ProjectPath 工程绝对路径
-Channel stable 或 beta；非交互必须明确选择
-SkillsDirectory Manual 的已配置 skills 根，安装器追加 letsgal-authoring
-DshHome DSH 实际数据目录；显式值优先于环境默认
-UserHome 实际用户主目录，隔离安装检查可用独立目录
-NonInteractive 非交互执行；不会替你解决路径歧义或修改冲突
-ReplaceModified 比较并明确批准后，完整备份已修改载荷再替换

安装器不自动扫描自定义 CODEX_HOME 或便携目录。目录兼容、同名入口处理和 DSH 配置详见兼容说明。不要关闭系统保护来绕过执行策略；可按客户端要求手动安装。

macOS／Linux 或自选环境：仅复制所选通道的完整 skills/letsgal-authoring 目录到已配置的 skills 根，保留原版备份和随包风险说明，再核实际发现。不要混合两通道或只复制 SKILL.md；Windows 安装程序的验证范围见下方说明。已有用户区保持，首次需要偏好时在实际用户主目录建立相应文件。

遇到安装差异

目录重叠时重新选择互不包含的包、技能与用户区位置，不删除个人区绕过。安装锁被占用时等另一个安装结束，不删除活动锁。如果 Skill 已完成但选项或日志保存失败，核真实文件、备份路径和提示，下次重新选位置，不反复强制覆盖。
