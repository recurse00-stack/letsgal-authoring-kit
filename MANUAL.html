使用手册

本手册对应 0.1.9。安装程序沿用0.1.5，版本工具补充2.5.0-beta.1资料选择与制作／排错说明。可直接打开随包 MANUAL.html 离线阅读与浏览器搜索。

这个包能做什么

letsgal-authoring 是给 AI 编程工具读取的社区 Skill。它教 AI 查找 LetsGal 官方规范、制作剧情与章节 JSON、组织协作和 Git，并保护已有作品。它不包含引擎、模型账号或 MCP，也不会给聊天工具凭空增加文件访问能力。

导入器只导入本包的 LetsGal Skill；“其他 Agent / 指定目录”用于选择 Agent 已配置的技能根目录，不是导入任意第三方 Skill。

第一次使用可依次阅读安装、工程版本、选择练习及字段说明，再查工具参数、排错和升级。Beta 专项与插件开发按当前任务需要阅读。

阅读入口：第一次使用 · 安装位置 · 手动安装与命令行 · 完整练习 · Beta 用法 · 工具参数 · 个人区 · 排错 · 更新与恢复。

安装与启用前：避免同类技能冲突

建议安装或启用本技能前，在 Agent 的技能设置中暂时停用其他功能重叠的 LetsGal／引擎创作类 Skill，避免重复触发、相互矛盾的指令和额外上下文开销影响执行效果。也请核对个人与工程范围是否装了多个同名副本。保留原文件及特调；由你决定停用哪一份，安装器不会自动禁用或删除其他 Skill。

停用后打开新会话，显式调用 letsgal-authoring 并核对实际来源。如果仍需其他专用技能，按任务单独调用，避免让多个入口同时接管同一项制作任务。停用方法以对应 Agent 当前的技能设置为准；没有停用入口时先查询其官方说明，不直接删除目录。

使用前的风险与保护

使用前请阅读：AI 可能误改、误删或泄露资料。请先备份作品并限制 Agent 可写范围；技能备份不包含作品。 本包按现状提供，不提供担保；作者及贡献者不对使用或无法使用本包造成的任何损失承担责任。详见风险说明与免责声明。

首次操作请先在工程副本上尝试，核对备份和恢复方法，再限制 Agent 的可写范围。安装器不负责备份整个作品；Git 也不一定包含未跟踪文件、素材或未提交修改。遇到删除、覆盖或批量迁移，先审查精确对象和影响，再授权。

安装界面顶部直接展示风险与免责摘要，可展开全文；命令行在任何文件修改前输出摘要和全文路径（包括非交互运行）。自动化调用者应把提示转交实际使用者，不能将捕获的输出当作用户已阅读。安装收据及安装／卸载日志记录说明版本与 SHA-256，仅用于本地追溯，未收集同意或放弃权利的记录。

手动复制 Skill 时，完整说明随 references/risk-notice.md 一起保留。AI 首次准备写工程时应核对可写范围、备份与关键风险；已说明且未变化时不必重复宣读，操作范围或风险变化时再作针对性提醒。

第一次使用

  1. 从社区提供的 GitHub Releases 下载 letsgal-authoring-kit-<版本>.zip，完整解压后可交给 Agent 按本手册协助安装。不要只下载 Install.cmd，也不要直接在压缩包中运行。
  2. 双击 Install.cmd，选择实际使用的 Agent。一般保留“个人 · 所有项目”；只给一个作品用时选择“项目 · 仅此工程”，再浏览项目文件夹。
  3. 检查蓝色预览区域中的安装位置、本包版本、已安装版本及状态；确定是你实际使用的 Agent 和范围后，点击“导入到 …”。窗口底部的固定状态栏会显示正在处理以及完成结果，无需在长页面里寻找反馈。
  4. 看到“导入完成”后，可展开“更多选项”点击“检查安装”。底部显示“检查安装 · 校验通过”（结果框标题为“安装文件校验通过”）后，点击“复制验证提示词”；在 Agent 中打开作品目录，建立新会话并粘贴。核对它实际读取的 Skill 路径，而不只看一句“已加载”。

普通导入使用 Windows 自带 PowerShell，不要求 Python、Node 或管理员权限。可选 JSON 检查器与版本资料工具需要 Python 3.9+。macOS／Linux、WSL 和远程环境请按 兼容表 手动复制到实际运行 Agent 的环境。

安装位置怎样选择

软件安装文件夹和技能目录是两回事。 把 Agent 或 LetsGal 装在 D／E 盘，不会自动把技能目录改到该盘；技能应放到 Agent 实际会读取的位置，通常不在程序文件夹内。

发行包没有绑定作者的本机用户名或绝对路径。Windows 安装器按运行它的用户主目录解析标准位置；请与 Agent 使用同一用户／环境，并核对预览。下表中的 ~ 指该环境的用户主目录；便携、WSL、容器或远程环境应核对其真实位置，并按对应手动说明安装。

需要 界面选择
Codex 个人安装／更新 选 Codex 和“个人 · 所有项目”；唯一已有 .codex/skills/letsgal-authoring 时沿用旧入口，唯一已有 .agents/skills/letsgal-authoring 时沿用它，全新默认 ~/.agents/skills
Codex 两处都有同名 Skill 自动选择停止；先核对实际加载来源，再选“其他 Agent / 指定目录”，明确使用其中一个 skills 根目录；原副本保留
仅某个作品使用 选对应 Agent 和“项目 · 仅此工程”，用“浏览…”选择或填写工程文件夹
自定义技能位置 选“其他 Agent / 指定目录”，浏览或粘贴该 Agent 已配置的 skills 根目录；不要选择末级 letsgal-authoring 文件夹

安装器会在所选 skills 根目录下追加 letsgal-authoring。自选目录不修改 Agent 的发现配置；若该位置尚未配置，先按 Agent 官方说明配置，再安装并验证。个人偏好与插件 Skill 仍保存在实际用户区，选项目或自定义技能根不会把它们打进公共 Skill。

只更改软件安装位置、仍使用标准技能目录时，选择对应 Agent 的个人模式即可。安装器只按上表规则和已有入口定位；不会扫描所有磁盘或读取 Agent 配置来寻找便携版、迁移数据目录或自定义 CODEX_HOME。软件另设了技能目录时，按以下步骤手动选择：

  1. 确认 Agent 已配置的技能根目录。例如 <自定义数据目录>/skills，尖括号内容替换为你的实际目录，这不是默认值。
  2. 选“其他 Agent / 指定目录”，点击“浏览…”或粘贴这个 skills 文件夹；不要选软件安装文件夹，也不要再选末级 letsgal-authoring。
  3. 核对预览显示 <自定义数据目录>/skills/letsgal-authoring 后导入；检查文件，再打开 Agent 新会话核对实际读取路径。

DSH 可在其专用选项内直接选择实际数据文件夹。首次默认取安装器进程的 DSH_HOME，未设时为 ~/.dsh；之后恢复上次成功选择。这个默认值不表示识别到了运行中的 DSH，启动器或提供器另设的数据目录须手动核对。

检查结果在哪里

“检查安装”位于“更多选项”内，展开即可点击。操作期间底部固定状态栏显示正在处理，结束后显示明确结果；页面结果框和中文详情同步更新。

操作结果 含义与下一步
导入完成 Skill 文件已安装；核对实际目录，再检查文件及新会话加载
安装文件校验通过 已装文件校验通过；详情说明已装／本包版本及是否一致，不代表 AI 已加载
需备份 已有内容需要保全；先比较，再决定是否“备份后继续”
操作失败 查看中文详情中的原因和路径；核对目录与权限后处理，不反复强制覆盖

DSH：选择其数据文件夹，默认通常为 ~/.dsh。如果启动器另设 DSH_HOME 或数据已迁移，浏览选择实际位置，不选程序安装文件夹。导入器会记住成功选择；它不会读取账号配置、改预设或重启 DSH。发现不到技能时检查默认技能根是否启用。

预览状态 你需要核对什么
未安装 目标下没有该 Skill；核对个人／项目范围和最终目录后安装
当前 已装文件与本包一致；无需反复覆盖，转到新会话验证加载
可更新 已装版本可识别，且与本包不同；核对两个版本，更新会先备份旧 Skill
需备份 已装内容有本地改动、文件缺失或来源无法核实；先比较并保全，确定后使用“备份后继续”

版本与状态只表示 Skill 文件和安装目标，不代表 AI 已调用它，也不代表 LetsGal 作品通过运行验收。已装版本无法识别时按未知处理，不能把它当成较旧版本直接覆盖。

安装位置若与本包来源、个人配置等受保护位置重叠，预览会提前拒绝，包括同一目录及目录互相包含。把完整解压包放在与实际技能目录分开的普通文件夹，再核对目标；不要通过删除个人区或修改保护规则来绕过。此处没有新增安装器原生操作截图，界面操作的本轮验证范围见 VALIDATION.md。

手动安装与命令行

macOS／Linux、WSL、容器或远程环境：把完整 skills/letsgal-authoring 文件夹复制到 兼容表 中该环境实际使用的技能根目录，保留目录里的许可证、参考文件和风险说明。个人区按需建立在实际 AI 用户主目录；已有偏好、插件库和旧版本不覆盖。安装后开新会话核对来源。本机安装不自动同步到远程环境。

Windows 完整包根目录的命令行入口：

powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -Harness Codex -Scope User
.\Check.cmd
.\Uninstall.cmd

-Harness 取 Codex、Claude、Cursor、Copilot、DSH 或 Manual；-Scope 为 User 或 Project。项目模式配 -ProjectPath "<工程绝对路径>"，Manual 配 -SkillsDirectory "<已配置的 skills 根目录>"，DSH 可配 -DshHome "<实际数据目录>"。-NonInteractive 适用于自动化；已有特调需先比较，明确使用 -ReplaceModified 才允许先完整备份再继续。命令行参数名与有效值以随包 Install.ps1 的参数声明为准；不要在其他工作目录单独运行摘出的脚本。

先明确工程版本

同一个 Skill 可以服务稳定版、Beta 和旧工程，但每个项目须按自己的实际版本工作。普通剧情任务不要求先取得整套 SDK；只在涉及扩展接口时核对对应 SDK。不要安装两个同名 Skill 来区分通道，也不要因为技能包版本带 preview 就切换引擎到 Beta。

在第一次任务中告诉 AI：

使用 letsgal-authoring。先核对本作品的 Studio 完整版本和稳定／Beta 通道；涉及扩展时再核对相关 SDK。沿用作品当前版本；不要升级引擎、迁移 JSON 或启用未经确认的新功能。版本不明时只读定位，告诉我当前任务还缺哪项依据。

此前观察的2.3.0-beta.1和2.4.0-beta.1官方新建空白工程的 version 和 engineVersion 均为 1.0.0，确切语义尚未确认；不要直接把它们传作宿主版本，也不要为消除冲突自动改值。版本信息可让 AI 写到工程 LETSGAL.md，以后重读沿用。版本与能力无法确认时，可以继续构思、文字草稿和只读查找；不要直接套用新 API。详细兼容规则

从选择练习走完一个最小完整案例

随包的选择练习包含一个完整章节：main 提问、两个选择、石桥／花园两个结果片段，以及返回 main 后的结束文字。它使用原创合成内容，不依赖角色、图像、音频或变量；已在 2.3.0-beta.1 有限预览过，加入你的作品后仍需从实际入口核对两条路线。

  1. 在 Studio 新建官方空白工程，或复制现有工程作为练习副本。确认 AI 当前打开的是这个副本，按前节核对完整宿主版本与通道。
  2. 让 AI 读取包内例子，重新生成章节及三个片段的唯一 ID，并同步替换选项中的目标 ID。若副本已有“选择练习”章节，先另取章节名，不覆盖原章；章节名和文件名一起修改。
  3. 将完整章节保存到副本的 chapters/选择练习.json；已另取名字时，文件名同步采用该名字。在已有 project.json 的 chapterOrder 中登记该章，保留原入口、其他章节及配置；不要用一小段索引示意覆盖整个 project.json。
  4. 对新章节和副本做只读静态检查，确认名称、引用及登记位置正确。章节中所有片段 ID 和 choices 内的目标 ID 必须对应；检查器的零错误还需要后续预览。
  5. 在 Studio 重新读取副本，打开练习章节的 main，从片段开头预览。先选“查看石桥”；重新从 main 开头预览，再选“查看花园”。只预览一个结果片段不能验证选项及回流。
  6. 对照下面的完整顺序。确认各路线仅显示自己的结果，然后显示回到路口的文字并执行 endChapter。记录实际宿主版本及通过／失败；保存、读档和导出另外验证，不能从这两次预览推定通过。
选择 应看到的文字顺序
查看石桥 “路口竖着两块路牌。你准备先查看哪一边？” → 选“查看石桥” → “桥栏上留着一道新划痕。” → “记下观察结果后，你回到了路口。”
查看花园 “路口竖着两块路牌。你准备先查看哪一边？” → 选“查看花园” → “花园门旁放着一把尚未收起的伞。” → “记下观察结果后，你回到了路口。”

可以把准备副本后的任务交给 AI：

使用 letsgal-authoring。只在当前练习副本加入包内“选择练习”章节，先核对实际 Studio 版本。重生成章节及片段 ID，并同步选项目标；保留原入口、索引和其他配置。若同名章节已存在，使用新名字。完成后只读检查，告诉我在 Studio 应从哪里预览，以及两项选择的预期文字顺序；未实际预览就明确说明。

本例的必要字段

这些字段帮助你读懂例子；完整结构仍按目标版本保存样本及 JSON 工作法核对。

变量与扩展的验证

涉及变量时，先列变量 key、类型、初值及保留方式。当前存档随读档恢复，跨存档共享，启动重置另设开关。回标题、读档和预览刷新不是全新启动；启动行为最终用导出游戏观察。制作流程与变量

扩展开发时区分作者设置与玩家存档，slot／shared／session 各自测试。代码写源码并构建，SDK 通过宿主同步，保持已使用清单 ID；扩展资源是否进入导出包要单独核实。扩展工作法

一个已实测的选择赋值例子（仅2.3.0-beta.1）

  1. 在 Studio 的项目变量页新建 BETA_SCORE，类型“数值”、初值0，保留方式选“当前存档”，不勾“每次启动重置默认值”。
  2. 选择这个目标变量，运算符用等号，操作数用字面量42。空操作数会显示表达式错误，填好后再保存。
  3. 在分支下方添加旁白 ASSIGN_RESULT_{BETA_SCORE}。原生保存的字面量 aLit 是字符串 "42"，不是数值 42；choices 仍是 JSON 字符串，改 JSON 时按真实样本保持这两层类型。从 main 开始调试，实际点击选项，确认结果为 ASSIGN_RESULT_42；编辑器实时预览显示42不能替代这次点击。
  4. 重新构建桌面游戏，在此处快存、另存一个空槽位，退出游戏并确认进程结束。重开后分别快读和读取槽位，核对文字、变量和场景。

选项“跳转片段”和“变量操作”是该面板的两种模式，切换后保存内容会改变。需要赋值后再调用片段时，将两个动作编排为明确的顺序，并按目标版本另做最小样例，不把此例硬改成同时支持两种动作。扩展追加历史不会自动随本例存档恢复；需要长期保留时，应先验扩展保存／恢复方案。

2.4 Beta的新入口怎样用

先确认实际宿主完整版本。以下皮肤／Tab说明依据 2.4.0-beta.1 公告与有限样本；2.4.0-beta.2 的修复说明见后文，不继承旧版实测结论。皮肤预设用于组合一套差分部位素材，不能只根据名字套用2.3的皮肤结构。建议在副本依次做：

  1. 选择一个差分角色及目标姿势，准备已有合法素材，配置并保存两个不同的皮肤预设；保留默认组合。
  2. 在两句对白的正文打开Tab菜单，分别选择角色、姿势、预设，再按距离与位置矩阵选择站位。显示名和结束行为在菜单底部核对。
  3. 为目标姿势设置头像裁剪，分别查看预览；每个姿势单独检查，避免把一份裁剪当作全部姿势。
  4. 保存后让AI只读比对角色与章节，记录实际引用。没有该版本保存样本时，不让AI猜写预设、头像或绑定字段。
  5. 从实际入口运行两句并恢复自动选择，观察换装、其他部位、站位、头像和对话结束后的状态。存读档与导出按当前作品需要另验。

长按Tab固定菜单与普通Tab打开是两个操作；长按期间的侧栏显示、拖边调整尺寸和姿势列表布局先在当前界面核对。删除姿势、预设和预制包操作使用副本并保留原素材。工坊扩展修复公告只描述引擎变化；本指南不因此替作品更新扩展或修改源码。

2.4.0-beta.1原生空白旁白可省略content；auto检查对此提示复核，不改原文件。新生成文本仍写数组，null／字符串／对象继续报错。

beta.1十三项、beta.2五项及各自实测范围见2.4专页和宿主验证。下节旧版实测仍限定为2.3.0-beta.1。

2.5 Beta：一个地点牌练习与排错路径

先核对当前实例完整版本为2.5.0-beta.1。下列路径依据官方公告与基础手册编写，本版新增功能还没有原生运行实测；按钮名称和保存字段以实际界面为准。完整AI指引见2.5专页。

在练习副本做一张地点牌：

  1. 添加浮动文字，写“旧港口”，为这条文字填写独立的浮字ID。先用普通文字确认位置，再按需要加局部样式、变量或文字动效。
  2. 选择无限停留，并确认不等待自然结束；历史记录开关单独设置。后面写两句普通剧情，验证地点牌仍显示而剧情能继续。
  3. 在离开地点的剧情位置添加隐藏浮字，填写相同ID；再加一句“已经离开港口”确认流程继续。不要留空ID来隐藏单条，基础手册的空ID会影响全部浮字。
  4. 从实际入口观察出现、推进和退场。再放第二张不同ID的牌，检查只隐藏第一张；查看历史是否符合开关选择。保存后让AI比对实际对象，未取样时只交付步骤，不猜写JSON。

本版公告的“等待结束”与基础浮字手册的“阻塞”措辞分别核对；关闭等待与不写历史是两个选择。有限时长的字幕按需求决定是否等待，无限文字不能挡住到达隐藏指令的剧情。

动态图像先在资产的模型库导入，再在角色表情中选择；模型封面、名称和真实引用分开。Spine一起检查骨骼、Atlas和纹理；Live2D检查入口及其依赖，负责构建的电脑按官方流程安装合法Core。先用模型预览，再走角色表情与一句对白，最后按作品需要导出；各阶段成功分别记录。旧内嵌模型配置可能迁移，先用副本读回，保留旧文件。详情见官方动态图像说明。

制作一个小片段

使用 letsgal-authoring。按现有作品风格，制作一段包含两个选择的剧情。先读工程约定，说明会改哪些章节和变量；只使用当前版本已有的指令，保留稳定 ID。完成后检查两条路线并说明实际预览是否通过。

排查 JSON

只读检查指定章节的 JSON 和引用，按本作品版本解释问题。未知字段先保留，不批量修复；列出可以确认的错误和需要宿主验证的部分。

本地检查命令（在完整解压包根运行）：

python "skills/letsgal-authoring/scripts/check_project.py" "<章节或工程绝对路径>"
python "skills/letsgal-authoring/scripts/check_project.py" "<章节或工程绝对路径>" --format json-only

默认 auto 识别片段结构；未知章节格式返回 unsupported_format。旧分支省略 mode 时按官方兼容默认 jump 检查并提示，原文件不改动；显式 --format fragments 仍只检查有限结构约定，不保证新建字段完整、角色引用或全部参数类型正确。json-only 只检查 JSON 语法。退出码 0 表示所选范围没有发现错误，1 表示有问题，2 表示无法检查／格式未覆盖；任何结果都不等于引擎运行通过。不要把“新版检查器不认识”当作删除旧字段的依据。

参数／结果 怎样使用或理解
path 必填位置参数：指定一个章节 JSON 文件或工程目录的绝对路径
--format auto 默认模式；只识别已覆盖的片段布局，旧分支缺省 mode 按兼容默认 jump 并提示
--format fragments 显式采用片段结构约定；仍是有限静态检查，不是完整 schema 校验
--format json-only 只检查 JSON 能否解析，适合先定位语法问题或未覆盖格式
退出码 0 所选检查范围没有错误；仍要阅读警告、未覆盖数和运行缺口
退出码 1 存在错误；按 issues 中的文件／位置核对，不直接批量修复未知字段
退出码 2 无法读取／检查，或格式未覆盖；核路径及版本样本，再选择合适范围

输出是 JSON 报告。errors 和 warnings 分别统计错误与提示；未覆盖章节、指令及未检查参数另列，read_only 表示工具没有改写输入。警告可以与退出码 0 同时出现，不能仅凭退出码省略报告内容。

在作品目录工作时改用 python "<实际 Skill 绝对目录>/scripts/check_project.py" "<章节绝对路径>"，版本工具同理。不要把包内相对路径直接当成任何工作目录都可运行的命令。

检查器对 callFragment → main 保留资料争议及目标版本核对提示，对存储引用环和深链给风险提示。它不运行 Studio 转换器，不推定禁用块是否转换、运行可达性或真实展开层数。前处理章节不因未列入普通章索引而建议加入。完整边界见 JSON 工作法及修订记录。

Beta main 调用及循环：有限原生证据

2026-09-30，在实际 LetsGal Studio 2.3.0-beta.1 的官方空白测试工程中，非循环 A → main 由原生片段预览显示 A 的进入标记、main 内容、A 的返回标记。此版本不能按“main 一律不可调用”判定既有数据损坏；新内容继续默认采用普通、无环、非 main 片段，这是制作约定。

三个循环用例（main → main、main → A → main、A → A）在原生调试中没有重复输出，继续执行调用后的内容；其中 main 自调用的原生 OP 仅 4 条。编辑器仍显示“最多静态展开 30 层”的提示，本轮观察不支持实际展开了 30 层。不能据此制作依赖递归退出的菜单，也不能把这几例推成所有循环的算法或深度保证。

以上只覆盖注明版本的有限调试／片段预览用例。Stable、独立玩家、导出、全局运行入口、禁用调用块、branch／if／扩展流程的 main 目标和一般深度策略仍需另验；官方 JSON 参考与调用片段手册的文字冲突也仍保留。详细公开范围见 VALIDATION.md，原始截图含私有界面信息，不随公共包发布。

更新、卸载与恢复

更新：下载新版完整包，解压到另一个普通目录，再运行 Install.cmd。预览核对本包／已装版本、状态及目标；Codex个人安装沿用唯一已有入口，两处都有时先明确选择，避免另建同名副本。相同安装位置会校验后更新，当前版本不反复替换。个人偏好、插件 Skill 和项目配置原样保留；缺失目录才创建，已有用户文件不重写。旧 Skill 位于所选 skills 目录旁的 .letsgal-authoring-backups，不会作为第二个 Skill 被发现。升级后打开新会话并重新核对实际加载来源，旧会话中的内容不能作为已使用新版的证据。

如果公共 Skill 被改过，导入器先停止。让 AI 比较原版与改动，将个人部分迁到外部配置；确认后用“备份后继续”。备份保留旧内容，但个人代码改动不会自动合并进新版。不要同时开两个导入窗口更新同一位置。

卸载：在“更多选项”中选择卸载，或运行 Uninstall.cmd。它将技能移到备份，保留整个用户区（个人偏好、插件 Skill、旧版 user.md）、项目文件与历史备份。

安装完成时会显示本次旧技能备份路径。日志位于 skills 旁 .letsgal-authoring-backups 的 *-install.json／*-uninstall.json。如果选项或日志保存失败，界面显示“有提示”，保留真实完成结果与旧记录；不要因此删除目录或反复强制覆盖，下次重新核对位置即可。项目内的备份可能带私有特调，提交 Git 前检查排除规则，安装器不修改项目的 .gitignore。

恢复：先保全当前目录和新增内容，找到结果或安装日志里的准确备份路径，再比较并恢复相应 Skill；不能通过删除所有备份来排错。导入器没有自动清理备份功能。
