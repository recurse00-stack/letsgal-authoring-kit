1. 入门、安装与确认 AI 实际读取

LetsGal Authoring Kit 是给 AI 使用的创作指南，帮助它选择接口、保留已有内容并检查结果。它不包含 LetsGal Studio、AI 模型或 MCP 服务。你仍在自己的 AI 工具中提出需求，在 Studio 中查看作品。

准备什么

准备完整解压的本包、能够访问本地文件的 AI 工具，以及作品的备份。只讨论故事可以暂不连接 Studio；实际修改工程还需确认版本、工程与 MCP。Windows 安装器使用 PowerShell 5.1 或 7，无需管理员、Python 或 Node；可选检查脚本才需要 Python 3.9+。

本包版本为 3.0.1 / 20261112-r5。Stable 对应 Studio 3.0 正式系列，Beta 对应 2.9 Beta 系列并兼容 2.8 Beta 系列。Skill 前两位与主要适配的引擎系列对齐，第三位用于本项目修订。当前 Stable 载荷为 3.0.1，Beta 为 2.9.0（保留 2.8 Beta 兼容路线）；安装器显示所选载荷的版本。完整安装包从 GitHub Release 附件取得。

安装一次

  1. 在完整解压目录双击 Install.cmd，不要在压缩包内运行，也不要单独摘出脚本。

  2. 选择工程对应的正式版或 Beta，再选实际使用的 Agent。通常选“个人 · 所有项目”；只给一个作品使用时选“项目 · 仅此工程”。

  3. 核对最终目录、所选／已装通道、版本与修订，再导入。目录应为 AI 实际发现 Skill 的位置，不能选 Studio 的程序文件夹。

  4. 展开“更多选项”，点击“检查安装”。底部状态栏应显示“检查安装 · 校验通过”，结果框显示“安装文件校验通过”。

  5. 打开 AI 的新会话，进行下面的读取核对。接着核对 AI 实际读取的来源。

安装器仅替换所选 Skill，保留个人偏好、插件资料和旧版备份，不安装或升级引擎。两个位置已有同名 Skill 时先确认实际加载来源；不要随手复制第三份或删除未知副本。

怎样确认 AI 真的读了

可以直接发送：

请使用 letsgal-authoring，实际读取你发现的 SKILL.md，告诉我加载路径、版本、修订和通道。读取已有的个人偏好，并说明本次任务会用到哪些约定。先只核对，不改工程。

预期得到具体来源及匹配的 metadata，而非“我会使用这个技能”。继续给出一个局部改句任务时，AI 应读取目标原文及相关专题。插件资料的核对见个人偏好与插件指南。核对来源与相关约定即可。

如果只有安装成功消息、旧会话仍回答旧修订，先新开会话并核实际路径。若新会话也找不到，查Agent 目录说明，确认该客户端支持本地 Skill、所在环境和发现配置。粘贴指南文字不会赋予文件权限或 Studio 控制能力。

首次需求怎样写

在“序章”的“车站”片段里，只把售票员第二句改得更简短。先读前后文，保留样式、行 ID 和配音绑定；给我改动前后对照。其他句子不改。

先给工程、位置、目标和边界，AI 可以在授权范围内完成读取、修改与必要检查。尚未决定写入时说“先讨论／先给候选”。已有内容和采用的定稿继续受保护；新写且未定稿的受托草稿可按目标迭代。恢复准备见第 7 章。

下一步：连接工程 → 一次完整的剧情练习。

2. Stable／Beta、工程身份与 MCP

准备什么

确认目标作品、运行中的 Studio 完整版本和已安装 Skill 通道。保留 -beta.1 等后缀。引擎身份以“关于”或当前运行实例返回的版本为依据。

目标 Studio 选择的载荷 资料范围
3.0.x 正式版 Stable 3.0.x 当前正式系列 MCP 工作流
2.9.x-beta.* Beta 2.9.x 嵌套剧情等 2.9 指导
2.8.x-beta.* Beta 2.9.x 的兼容路线 使用明确保留的 2.8 指导
2.5.0 历史发行 使用当时的完整资料与包
其他／不明／来源冲突 暂停工程执行并核身份 版本差异需本次明确许可；可继续讨论和只读核对

开工检查只在首次工程操作时静默进行，同一实例和任务复用；发现升级、热更、重连或接口差异时才重新核对。不会每轮对话联网查更新，纯讨论不触发。

本包编号从 3.0.0 起按引擎系列组织：前两位表示主要适配系列，第三位用于 Skill 自身修复、小功能和同系列适配。当前 Stable 为 3.0.0，Beta 为 2.9.0，并保留 2.8 Beta 兼容路线。

开工比较前两位与实际发行身份。同为 3.0 正式系列时，3.0.0、3.0.1 和不同界面热修复可直接使用对应资料；无需专门查询补丁号或哈希。运行版本为 3.0.0、更新设置选择 Beta 时，仍选 Stable；正式版与 -beta 的实际身份分别处理。

主次版本超出维护／兼容范围，或实际发行身份不匹配时，AI 暂停目标执行并向当前使用者说明差异、请求本次范围许可。系列和身份未变即可复用，补丁变化不单独重新询问。来源冲突或连错工程先核对目标。

切换 Skill 不会切换或更新引擎。同一个技能目录只安装一份同名入口；不同版本的作品可以使用各自项目范围，但要核对 AI 的发现优先级。

连接到正确工程

按官方 MCP 接入指南，在目标 Studio 窗口取得该窗口提供的真实连接地址，再配置到 AI 客户端并批准所需连接。网页中的示例地址只作格式参考。不要使用别人截图里的端口，也不要把令牌贴到公开反馈中。已配置连接时先验证，不必重复安装或重注册。

请先读取当前 Studio 状态，核对版本、工程名称和 project.id、连接权限、可用工具组及待保存状态。我这次要改的是“星港练习”。若连到别的工程，先停止写入并说明差异。

预期看到来自当前 MCP 返回的身份。多个窗口可能对应不同端点；窗口标题相同也不能代替 project.id。连接成功、获得写权限、一次具体高影响操作获批是不同状态。

切换工程与独立窗口

3.0 的 studio_open_project 可打开已有工程，会在当前窗口保存并关闭原工程；需要新建工程或独立窗口时使用相应的界面入口。需要保留原工程时，应使用目标已有窗口，或明确授权一次新窗口初始化。2.9／2.8 不套用这个 3.0 入口。

切换、重连、长时间等待确认后，AI 应重新读身份、权限和当前内容版本（revision）。旧 revision 是冲突检测依据，不能一直重复使用。

遇到差异怎么办

现象 怎样继续
等待连接批准 在目标窗口确认连接；AI 继续可做的只读资料工作
只读或明确拒绝 保持权限边界，先给草稿；不能绕到磁盘或界面强写
工具没出现 定向发现并真实调用状态工具，失败后有限尝试单服务器重连
有工具却超时，写入结果未知 先读目标和操作记录，确定是否已经落地；不要整批重发
仍无法连接 说明已尝试步骤；需要界面兜底时再按任务授权使用

没有 MCP 时仍可讨论、制作草稿或维护独立扩展源码。直接离线写工程前，需要正常保存关闭目标工程并确认其他实例已释放。Computer Use 是必要兜底，日常制作优先专用 MCP。

查阅：只读版本命令

在完整包根目录运行；不会探测、启动服务或修改工程：

python "channels/stable/skills/letsgal-authoring/scripts/inspect_version.py" --studio-version 3.0.0
python "channels/beta/skills/letsgal-authoring/scripts/inspect_version.py" --studio-version 2.9.0-beta.1

工程执行检查加 --gate 即可，--studio-version 填目标实际完整版本。operation_gate 的 matched 表示身份匹配，confirmation_required 表示需本次许可，identity_required 表示先查身份。--update-channel beta 只记录更新偏好；不改变实际版本判断。

可用参数还包括 --studio-exe、--project-version、--channel、--sdk；项目参数只填明确固定的目标引擎版本。reference_selected／退出码 0 表示选到资料；UNKNOWN／退出码 2 表示缺失、冲突或未登记。资料路由结果与工程操作准入结果分别读取。

3. 一次完整的剧情修改与分支练习

准备什么

使用独立练习工程或作品中的获准测试章，先确认版本、工程身份及覆盖章节的恢复点。以下新建练习面向 3.0／2.9 的嵌套选项；2.8 让 AI 按该版的 branch／结果片段结构实现相同行为，不直接复制嵌套标记。

从一句话到两个选择

先发出完整目标：

在独立练习章新建“车站选择”。先显示“列车即将出发。”，给出“问路”和“候车”两个选项。选“问路”显示“站务员指向二号站台。”，选“候车”显示“你坐到长椅上。”。两条路线结束后都回到“广播再次响起。”。不改原有章的入口和顺序，告诉我怎样从本练习开头预览。

AI 应先取正式章／片段 ID，再按当前宿主能创建的结构写入。3.0／2.9 通常把选项正文放在同一片段的嵌套菜单内；配对标记分别界定两条互斥路线的正文。完整 JSON 示例分别在 Stable 样例和 Beta 样例，可用来核对结构；写入时保留作品已有配置。

预期剧情：

列车即将出发。
  问路 → 站务员指向二号站台。
  候车 → 你坐到长椅上。
两条路线均继续：广播再次响起。

怎样核对

  1. 查看改动摘要：新增了哪个章、片段，原有入口是否保持。
  2. 确认写后从 Studio 读回，选项、两段结果和共同尾句都在；结构校验没有未处理错误。
  3. 从练习开头选“问路”，应只出现问路结果，再到共同尾句。
  4. 重新从开头选“候车”，应只出现候车结果，再到共同尾句。分别记录两条路线的结果。

选项出现但无结果时，核本版结构的目标 ID 或路线边界；两路混播时核菜单结束标记及尾句位置。根据读回的结构做局部修正。

再做一次局部改字

只把“你坐到长椅上。”改成“你坐在窗边的长椅上。”。保留这行原有的颜色、粗体、ID、语音与其他字段；展示改前改后，并读回确认。

AI 应在原富文本内只改对应文字。行 ID 关联翻译或音频，不能为改一句话重建整行。旧配音绑定可以保留，但台词改变后应提示录音可能不再匹配，是否重录由本次需求决定。

加条件时怎样提出需求

在练习里用现有布尔变量 hasTicket 决定提示：true 显示“请进站”，否则显示“请先买票”。先核实变量确实存在、类型和作用域，不擅自更名或建立同名变量。

预期条件分支互斥；最终 else 没有额外条件。检查变量初值、修改位置和两条结果，而不只看代码格式。旧版 branch、if 与普通片段调用有各自的返回和跨章规则：3.0 的旧 branch 可按契约调用唯一启用的跨章片段，普通 call 与 Beta 仍按各自版本契约使用。

查阅：结构检查器

在完整包根运行（其他工作目录改用脚本绝对路径）：

python "channels/stable/skills/letsgal-authoring/scripts/check_project.py" "<章节或工程绝对路径>"
python "channels/stable/skills/letsgal-authoring/scripts/check_project.py" "<章节或工程绝对路径>" --format json-only

Beta 改为相应目录。检查器只读文件；JSON 输出与退出码说明见格式专题。退出码 0 仍需阅读 warnings；资源引用、条件含义与玩家路线还需在作品中核对。遇到未来格式先用 json-only 核基本 JSON，再查目标宿主实际样本，不自动迁移格式。

下一步：舞台、演出和配音；失败与撤销见精确恢复。

4. 舞台、演出、多语言与配音

准备什么

准备已获准使用的角色、背景和音频，说明目标章节、效果及目标语言。先核实际资源 ID／路径；配置存在、剧情引用和实际播放是三个检查点。删除素材前还要核引用和备份。

让角色完成一段演出

在车站练习开头显示角色阿岚，先淡入，再向右平移，最后回到静止状态。已有角色布局和口型设置保持。请选用当前版本可创建的指令；完成后从这段开头连续预览，并说明检查到的效果。

AI 应读取角色布局与工程预设，把需要的配置和剧情启用连起来。普通显示／更新／移除角色、镜头控制与演出段按任务选用；旧镜头动画可以维护，不因版本更新自动迁移。

核对对象、移动方向、时长、镜头跟随和最后位置。连续播放以核对过渡过程，有画面判断价值时再用预览捕获。后台循环必须有明确停止路径，例如离开场景时停止呼吸以外的循环段。

3.0 r3–r5 的演出编辑变化

  • 立绘站位：r3 起，对白、显示立绘和更新立绘可选择预设或自定义位置。提出需求时说明是采用工程预设，还是延续已有自定义位置；在场角色的移动使用“更新立绘”，核对起点与最终位置。人工预览支持拖动、缩放和旋转，AI 仍按当前块接口编排。
  • 文字排版：r3 增加中文标点换行规则，可按项目开关；对白与旁白检查器可进入文字排版设置。遇到行首句号等问题，先核排版设置与实际显示，保留原文标点。
  • 声音时间轴：r5 的全屏演出段编辑器显示音频波形，并体现循环、淡入与淡出。波形便于对齐演出，最终仍通过试听核对节奏。
  • 长章节工作：r3／r4 改进剧本编辑与预览，r5 进一步优化 300 块以上章节的载入、输入和定位，并修复载入后部分编辑操作失效及章节多选删除。AI 读取长章继续处理分页和 revision，按任务范围局部修改。

以上为官方更新说明中的变化；本项目的定向复测范围见验证说明。

口型与配音

给这三句绑定准备好的原声录音，保持其他句子的音频。先预演匹配范围，读回行与录音的对应关系，再试听这三句。缺资源时列出缺项，不用同名文件猜配。

先核语音表的映射键与台词行，预演自动匹配，避免覆盖已有录音。文字口型与音频口型依目标版本和角色配置选择；配置校验与真实听感分别确认。语音识别工具缺席先查工具组及权限，不直接推断宿主无配音能力。

多语言练习

为车站练习增加英语译文与英语配音，原文、原声和其他章节不变。保留稳定行 ID；发现源文已改时只处理受影响条目。请分别核对文字语言、配音语言、录音键以及缺失英语录音时的回退。

3.0／2.9 的译文写入按条返回结果，同批可以部分成功。AI 应保留成功项，只对 sourceHash 过期的条目重读源文并重新翻译。文字显示语言与配音语言可分别选择，Studio 自身界面语言是第三项设置。个别行的语言覆盖与语音表匹配不同；移除覆盖后恢复语音表匹配；静音需另行设置。

预期交付包含：改动的行、每种语言的文本／音频对应关系、实际读回和试听范围。检查切换文字、切换声音、缺失录音回退以及临时预览设置恢复。2.8 的具体能力按 Beta 对应资料选择，不套用后来新增行为。

遇到差异怎么办

看不到预览时先处理可见性和运行状态，不要反复抢前台。导入／删除报错时读回登记、文件和隔离区，区分已完成与剩余项。需要追溯同类现象时，可查自测记录。

一个地点牌小练习

在独立练习章显示地点牌“旧车站”，停留后关闭并继续对白。优先复用工程现有 UI 和动作；不替换标题页、菜单或主题。请告诉我打开与关闭的入口，并验证关闭后对白仍能继续。

若本次需要独立 UI 文档，AI 应先读目标 schema，用实际返回的元素 ID 修改。整页替换必须保全原文、稳定 ID、状态、动画和引用。

数据表怎样核对

在练习数据表添加一个测试物品“车票”，价格 12；先读现有字段、类型和行 ID，保留其他行。将它显示到测试列表，再核对读回与界面取值。

数据表是结构化条目，行 ID 常被界面和剧情引用。新增／改值后核字段和引用；运行副本及存档行为另验。需要删除时先有覆盖集合文件的历史恢复点。project_delete 不支持普通 undo，恢复原行按限定历史恢复处理，确保原 ID 与引用一并恢复。

需要开发扩展时

现有方法不能表达这段规则。请先核目标 SDK 与公开接口，给出最小实现，保持原插件 ID、源码关联和现有设置。分别报告类型／构建、Studio 加载、方法调用和存读档检查。

普通玩家界面与供作者使用的 Studio 组件分开实现。参数和预设按目标 SDK 真实类型填写；Stable 3.0 的新增字段不能直接写进 2.9／2.8。调用方法前核类型、范围、枚举与资源引用，并用代表输入检查业务结果。

状态分清作者配置、单槽存档、跨档数据和本次启动状态。恢复存档时可能重新经过逻辑入口，奖励／扣款等副作用需要按 SDK 的恢复语义处理。是否在 Studio、Player、Web 或导出中测试，分别报告。

重置设置会恢复声明的默认态。先保存原值，写后核对设置值与 isDefault；没有声明默认值的字段可以缺少值。历史现象与新版复测见设置与恢复记录。

6. 个人偏好与作品约定

三种资料放在哪里

~ 指实际运行 AI 的用户主目录；WSL、远程环境或另一账号可能是不同目录。

内容 位置与用途
跨作品偏好 ~/.letsgal-authoring/preferences/user.md，例如文风、命名、窗口使用习惯

给插件建立指南

插件指南属于独立的 Skill Wiki 区域，按真实 ID、版本和修订查找；这里保存你的个人约定。建立指南、读回正文与处理索引缺失的完整步骤见该区域。

平常使用时怎样确认读取

跨作品偏好与具体作品规则分别维护；更具体的工程要求适用于该工程，当前请求决定本次任务范围。读取资料并不授予额外文件或工具权限。

暂停资料保留文件并跳过正文加载。含私人内容的工作台请单独保存，分享注意事项见隐私说明。

8. 更新、切换、卸载与备份恢复

更新或切换前准备什么

准备完整的新包，确认当前安装路径、通道、版本及修订，并备份作品与需要迁移的个人资料。同一产品版本可能有不同候选修订；“内容不同”不表示哪一份更新。未标注修订的旧包也不能凭目录日期猜先后。

用同一安装器更新

  1. 把新包完整解压到另一普通目录，运行 Install.cmd。
  2. 选择同一实际 Agent 位置和所需 Stable／Beta。核对预览中的已装与本包信息，再导入。
  3. 内容一致时应校验后保持不变；内容不同则先完整备份旧 Skill，再安装所选载荷。
  4. 检查安装，并在新会话核实际路径和修订。新会话应能读到所采用的修订。

个人偏好、插件知识和作品配置保留，主包不升级宿主、不启用暂停资料。遇到已安装文件被个人改动，先比较并把个人部分迁到用户区；只有明确选择“备份后继续”才替换，旧改动不会自动合并进新版。

备份在哪里，怎样恢复

旧 Skill 存在 skills 目录旁的 .letsgal-authoring-backups，安装结果及 *-install.json／*-uninstall.json 日志记录准确备份路径。备份不会作为第二份 Skill 自动发现。不要通过清空所有备份排错。

请找到上次安装日志指向的旧 Skill 备份，比较当前与备份的通道、修订和文件。先保全当前内容，只恢复指定 Skill，个人区和工程文件保持；恢复后校验文件及新会话读取。

恢复前保留当前新增内容，按准确目录核对后恢复；不复制到另一默认目录制造同名入口。个人区要另行备份，安装器旧 Skill 备份不包含它。备份可能有私人特调，提交 Git 或公开分享前检查内容。

卸载与换电脑

“更多选项”中的卸载或 Uninstall.cmd 会把当前 Skill 移入备份，保留用户区、作品和历史备份。引擎及插件的安装保持原状。

换电脑、账号、WSL 或远程环境时，在实际运行 AI 的环境另行安装；只按需要复制自己的偏好与插件资料，再核路径和版本。迁移材料作为个人备份单独保存。

-DshHome DSH 实际数据目录；显式值优先于环境默认
-UserHome 实际用户主目录，隔离安装检查可用独立目录
-NonInteractive 非交互执行；不会替你解决路径歧义或修改冲突
-ReplaceModified 比较并明确批准后，完整备份已修改载荷再替换

安装器不自动扫描自定义 CODEX_HOME 或便携目录。目录兼容、同名入口处理和 DSH 配置详见兼容说明。不要关闭系统保护来绕过执行策略；可按客户端要求手动安装。

macOS／Linux 或自选环境：仅复制所选通道的完整 skills/letsgal-authoring 目录到已配置的 skills 根，保留原版备份和随包风险说明，再核实际发现。不要混合两通道或只复制 SKILL.md；Windows 安装程序的验证范围见下方说明。已有用户区保持，首次需要偏好时在实际用户主目录建立相应文件。

遇到安装差异

目录重叠时重新选择互不包含的包、技能与用户区位置，不删除个人区绕过。安装锁被占用时等另一个安装结束，不删除活动锁。如果 Skill 已完成但选项或日志保存失败，核真实文件、备份路径和提示，下次重新选位置，不反复强制覆盖。

本包当前验证边界见验证范围，宿主操作证据见宿主范围。

插件 Skill Wiki

这里收纳插件配套的使用指南。主 Skill 负责 LetsGal 的通用制作方法；插件 Skill 补充某个插件的真实方法、参数和例子。安装结构中的 plugins/ 对应这个区域，个人偏好则在“个性化”区域。

先找到正确版本

准备插件的真实清单 ID、版本／修订、目标 Studio 版本，以及作者说明或源码。按清单 ID 区分插件，同一个插件的多个版本可以分别保留。

请核对当前工程使用的插件 ID、版本和启用状态，读取匹配版本的插件 Skill 及本次任务所需引用，再说明怎样完成这个需求。不要自动升级插件。

AI 应实际读取 ~/.letsgal-authoring/plugins/<插件ID>/<版本>/SKILL.md。有 plugins/INDEX.md 就按索引找；索引缺失时，定向检查已确认 ID 和版本的目录。嵌套 Skill 没有出现在全局技能列表中，不妨碍主 Skill 直接读取正文。

建立一份可用的插件指南

请分析我指定的插件，按真实 ID、版本和修订建立插件 Skill。写清方法、参数、完整调用例子、存档影响及验证范围。保存到用户插件区，更新索引；从主 Skill 的查找路径读回正文和必要引用。不要因此安装或启用插件。

可以采用插件写作模板。面向 AI 的 SKILL.md 说明如何选接口；面向创作者的 Markdown 手册说明准备什么、怎样使用、预期结果和核对办法。两种文档可以引用同一份参数资料，不必复制两套定义。

保存后从索引进入实际正文，并核对所需引用。未知参数仍需查证；版本冲突先核对工程实际使用的版本，不默认采用最新资料。

让指南出现在工作台

在对应插件版本目录提供 wiki.json，登记人类手册的标题、版本、状态及 Markdown 文件。运行本地工作台生成工具后，符合格式的条目会自动列入本区域，并参与全文搜索。具体格式和完整命令见资料接入。

页面上的“可阅读”表示手册已接入。插件的安装、启用及作品验证在 Studio 中分别确认。暂停条目只显示身份和状态，正文不载入。

看到了资料，但 AI 没有使用

请不要只报告“发现指南”。实际打开匹配版本的 SKILL.md，并沿相对链接读取本次用到的方法说明；告诉我采用的 ID、版本和修订。

如果指南与真实接口不同，保留具体差异，按当前工程的清单、SDK／源码及实际返回继续核对。让资料显示在这个人类 Wiki 中，与让 AI 按任务读取插件 Skill，是两条互补的路径。

接入我的资料

工作台提供两个扩展位置：Skill Wiki 接插件手册，个性化 接个人偏好和作品约定。它们与安装器保留的 plugins/、preferences/ 用户区对应；主包的通用说明继续在“主体”中。

日常怎样阅读

公共 MANUAL.html 可直接离线打开，左侧切换区域，搜索框按全文查找；Ctrl+K 定位搜索，清空后继续阅读，浏览器后退可回到上一章节。“完整阅读与打印”展示全部正文，打印也包含所有已接入的可阅读资料。

公共页不会自行扫描硬盘。已有插件手册准备好接入清单后，让 AI 运行下面的本地生成命令；生成的工作台会自动显示符合格式的条目。也可以在页面右上角“载入本地资料”，选择生成的 JSON，替换本次页面中的资料列表。页面内载入只保留在内存，刷新后恢复到 HTML 文件本身带有的资料。

给插件增加一个接入清单

在 ~/.letsgal-authoring/plugins/<插件ID>/<版本>/ 内放 wiki.json。以下为虚构示例，ID、版本和路径应替换为真实值：

{
  "schema": 1,
  "kind": "plugin",
  "id": "example.weather",
  "version": "1.0.0",
  "revision": "guide.1",
  "title": "天气示例插件",
  "summary": "天气切换的准备、调用与核对方法。",
  "status": "available",
  "documents": [
    {"id": "guide", "title": "使用指南", "path": "docs/USER-GUIDE.md"}
  ]
}

ID、版本必须与目录一致。documents 可登记多篇 Markdown，路径相对于清单所在目录；同包已登记文档之间的链接会转为工作台内跳转。已有手册不用搬出自己的版本目录。工作台按 ID、版本和修订保留身份，不自动选择最新版本。

给资料制作者的机器可读字段定义见 Wiki 清单 schema。清单字段检查之外，生成器还会核对目录身份、文件位置和重复文档标识。

status 可为 available 或 paused。暂停时只展示名称、版本和简介，正文跳过加载与搜索。生成器只接入资料，插件的安装与启用仍在 Studio 中管理。

接入个人资料

在 ~/.letsgal-authoring/preferences/wiki.json 使用同一结构，将 kind 设为 personal，例如 ID 为 my-authoring-notes，标题为“我的创作约定”。documents 中可以显式登记已有 user.md，也可登记同目录下单独维护的作品约定说明。真实作品规则仍以工程中的原文为准，这里是阅读入口。

生成器只读取清单明确列出的文件。不要为了展示建立第二份需要手动同步的偏好正本；已有偏好位于旧根目录时，可先保留旧位置，只接入单独的说明，或经核对后另行整理资料。

生成本地工作台

维护工具需要 Python 3.9+ 和 Python Markdown；普通阅读和主 Skill 安装不需要这些依赖。工具从完整包根目录运行，下面的尖括号替换为实际路径：

python maintenance/build_workbench.py --user-area "<实际用户区>" --check
python maintenance/build_workbench.py --user-area "<实际用户区>" --output "<新建的个人工作台.html>" --data-output "<新建的资料.json>"

--check 只校验清单和当前可阅读文档。第二条生成一份包含主手册与本地资料的完整离线 HTML，同时生成供页面载入的 JSON。输出目录需已存在，输出文件须是新文件，且位于公共发行工程之外；工具不会覆盖原页面或改写用户区。更新资料后再生成新文件，核对后自行采用。

JSON 接口名为 letsgal-wiki-library、schema 为 1，由工具生成。前端同时暴露 LetsGalWiki.register(data)，供将来的本地集成复用同一校验与展示流程。数据只有资料身份和正文；不支持执行扩展脚本、样式或嵌入窗口。

怎样核对接入结果

  1. 生成结果列出资料、正文和暂停条目数量；不符合格式时给出具体原因，原文件保留。
  2. 在对应区域核对标题、ID、版本和修订，打开正文，搜索一段独有文字。
  3. 从结果跳转到相关段落，再检查同包文档链接与打印。
  4. 暂停条目只能看到身份，不应搜到其正文。

含私人资料的 HTML、JSON 和打印稿请按隐私说明单独保存与分享。点击外部资料链接会离开离线页面。
