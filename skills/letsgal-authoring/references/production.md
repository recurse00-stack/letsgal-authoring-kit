# 从制作目标到可玩片段

先确定玩家本次会看到什么、做什么、得到什么反馈及何时结束。新作的主角、结论或玩法核心仍需用户决定；不影响方向的占位可标明为临时。已有作品沿用设定、声线、稳定 ID 和现有入口，旧原型不自动成为正文。

## 选正确的制作层次

新工程优先由 Studio 生成骨架；无法控制编辑器时完成独立内容并说明导入步骤，不凭猜测拼完整 project.json。文字草稿、导入文本、章节源 JSON 和可运行工程分别交付。纯 Skill 不提供任何模型或控制能力。

| 当前层次 | 制作与观察 |
| --- | --- |
| 章内线性片段 | 编排 Block、选项和结果；调用片段结束后回到调用处，检查是否重复发放奖励 |
| 基础跨章调度 | 核对章索引、入口和停用状态；正文结束／endChapter 不等同于整个作品已结束 |
| 蓝图调度 | 仅用于实际启用该模式的工程；核对入口、候选、条件、空候选和终点，画布位置不是执行顺序 |
| 前处理章节 | 在目标调度资料中核对用途，不加入普通章顺序或候选池，不用普通剧情示例覆盖其结构 |

蓝图及相关新变量功能有 v2.0.0 官方版本说明，旧版不默认套用。[章节调度](https://docs.avg-engine.com/advanced/chapter-scheduling)与[版本选择](version-compatibility.md)

## 变量和素材

从当前工程取得变量 key、类型、默认值、读写者和保留策略。项目变量的“当前存档／跨存档”与“每次启动重置”分开设置；启动重置不是第三种范围。读档、回标题、返回入口、局部预览重载和全新启动不能互相代替。项目启动重置也不等同于扩展 save schema 的 session。[官方变量说明](https://docs.avg-engine.com/advanced/variables)

需要状态改变时先列初值、触发动作与期望值，在运行数据查看器或用户可见反馈中观察。更改 key 或含义需查扩展中的字符串消费者和旧存档影响；不能从 UI 显示推断已经落盘。

核对实际角色、场景、表情／皮肤、素材和授权。缺资产就报告缺项，获准时用可识别占位，不静默替换为空白图。2.3 Beta 姿势／部位与普通表情不是同一种引用结构，写入前取该版保存样本。

## 一个完整的小案例

[选择练习](../examples/选择练习.json)的两项选择分别进入两个非 main 片段，显示结果后回到主线。加入隔离工程时重生成 ID、在既有普通章索引登记，保留原入口和配置。先静态查引用，再从实际入口各走一条路线；应看到对应结果及回流后的主线。它是合成练习，不包含用户作品或已验收的宿主记录。

复杂片段仍围绕进入条件、动作、反馈、离开条件制作。把角色心理描述与游戏状态区分；条件边界、无资源／无候选、重复进入和失败分支需要可观察结果。

## 验证与交付

只运行与本次改动相关的验证，复用仍适用的结果并标明版本。文件差异与静态检查 → 当前宿主局部预览／完整调试 → 保存读取及全新启动 → 请求的导出平台，各自记录。涉及启动行为时最终用导出游戏验证，不能用刷新预览冒充关闭后重新启动。

素材许可、私人信息和秘密检查针对实际候选包。导出和外部发布按当前任务授权执行，不随更新 Skill 自动发生。交付说明修改文件、玩家行为、实际通过范围、剩余缺口与恢复入口。
