# 从需求到可玩的内容

## 新作与已有作品

新作先明确受众、题材、玩家操作、预期规模和本次片段的结束条件。缺失细节若不影响方向，使用明确标注的临时方案；涉及主角设定、剧情结论或玩法核心时与用户小批讨论。优先使用 Studio 生成的基础工程，不把一个章节示例称为完整游戏。

已有作品先看当前入口和此次涉及的章节、角色、场景、变量及扩展说明。保留既定设定、写作声线和 ID。把用户确认、临时提议、历史版本分开，不能因为某段旧稿可读取就采用它。

## 一个片段的制作步骤

1. 写一小段场景目标：进入条件、玩家动作、关键反馈、离开条件。
2. 列出分支和状态变化：选择前提、结果、需要记忆的变量、汇合位置。区分角色心理描述与真实玩法状态。
3. 核对真实角色、表情、场景、音频和变量标识。缺资源时写明缺项；允许占位时使用项目内可识别的占位内容，不伪造已有资产。
4. 在目标章节中编排内容和演出。文本草稿、导入文本、磁盘 JSON 和引擎编译数据是不同交付物，使用用户要求的形式。
5. 检查玩家能否理解选项、每个结果是否有反馈、结局是否真正结束、返回与重入是否重复发奖励。
6. 在实际入口测试本次相关路线；涉及持久状态时检查保存、读取、重新进入和初始化。最后按目标平台要求验证导出，不从编辑器预览推断全部平台行为。

## 蓝图与变量

官方说明将蓝图调度标为 v2.0.0 新增；旧版或版本不明时，先按 [版本兼容](version-compatibility.md) 判断可用性。目标宿主支持且工程已选择蓝图时，再处理章节与决策节点；不能为使用本技能自动切换模式。修改前确认既有模式与入口，检查正文、出口、空候选集合、条件边界和流程终点。参见 [官方蓝图说明](https://docs.avg-engine.com/advanced/chapter-scheduling)。

变量定义从当前工程和官方相关字段说明取得；明确类型、初值、谁写谁读及生命周期。不把 UI 上临时显示的值当作已持久化数据。更改字段名称或含义时搜索消费者和旧存档影响，按需求设计迁移。

## 素材与发布

素材采用什么目录、命名和授权，由项目确定。只复制或转换所需文件，保留原始来源与许可。缺失文件应可定位；不要通过静默替换、空白图或吞掉异常掩盖问题。

制作与发布分别验收。导出、上传工坊、公开仓库和公开作品须处在用户当前授权范围；发布前检查候选包的素材权利、个人数据及密钥。这里要求检查实际包含的文件，不要求无关的通用合规清单。
