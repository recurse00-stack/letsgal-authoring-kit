# LetsGal 设计参考：制作人的日常

供需要相关设计方法的创作者独立选用，帮助把“希望玩家感受到什么”变成可比较的安排。依据《制作人的日常》0.1.1 提炼十条方法，重心是基础场面、信息反馈与轻经营循环；精细音画同步和复杂情绪演出需要另找证据。

**这是参考。当前具体要求、作品约定和个人偏好优先。** 偏好的读取、分区与冲突处理继续由主 Skill 的个人定制机制负责；本包不保存偏好副本。独立调用时也以当前请求和已有创作上下文为准。

## 按问题读取

| 正在解决的问题 | 专题 |
| --- | --- |
| 人物怎么站、何时进退、切换如何表达变化 | [演出与转场](references/staging.md) · D01–D02 |
| 玩家注意哪里、如何知道结果、下一步做什么 | [界面与反馈](references/feedback.md) · D03–D04、D10 |
| 自由探索与正式进展、随机日程、短事件、关系与结算 | [事件与经营](references/events.md) · D05–D09 |
| 核对样例到底实现了什么、来源能支持多强的结论 | [来源与证据范围](references/sources.md) |

只选与当前问题有关的方法。没有适合的方法就沿作品目标设计，不为使用本包补进经营系统、数值好感或镜头运动。

## 用法

先从上下文确定本段要传递的关系、信息或选择压力，再提出安排及其作用。已有明确偏好直接应用；需要比较时给出实质不同的少量方案，说明各自代价。材料里的参数、两选结构与行动顺序均为样例选择。

改编方法时至少想清楚：玩家会看见什么、做什么、收到什么反馈；在哪种条件下应删去或换法。回复可直接交付场面安排或修改建议，不必机械输出整套方法卡。

需要落地到工程时，回主 Skill 按实际通道选择能力与实现资料：场面和媒体查“舞台与素材”，连续编排按需要查“演出段”，界面查“UI 与数据”，分支和状态查“剧情与配音”。设计上的停顿不自动等于时间轴指令；本包也不要求安装样例扩展。讨论和草稿不自动变成工程写入。

评估时对照原目标检查：人物关系是否读得出，选择前信息是否恰当，反馈能否解释后果，重复一轮后是否仍有必要。区分文本推演、实际预览和玩家体验证据；来源实现过某个安排，只能支持把它作为候选。
