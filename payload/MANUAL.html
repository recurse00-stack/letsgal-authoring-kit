扩展界面设计参考

这是 LetsGal Authoring Kit 的可选附属包，帮助你和 AI 设计扩展设置页、参数检查器及编辑预览。它提供可改编的方法与案例；主 Skill 负责工程实现，具体插件指南负责该插件的参数与用法。

从一个需求开始

准备扩展要解决的问题、已有参数和作者常做的操作。例如：

这个提示卡扩展有文本、位置、颜色和显示时长。请按我的现有参数，比较单页分组和分页两种方案，说明各自适合什么情况，先不要改代码。

预期得到页面结构、字段组织、预览内容和主要取舍。核对常用操作能否顺利完成、已有选择是否保留，再决定是否实施。

使用路线

  • 安装、启停与工作台
  • 设计练习与核对
  • 来源与适用范围

已有明确布局时，可直接请 AI 按该方案实现；无需每次重新设计。安装本包不会安装“Studio 组件包演示”或任何运行插件。

安装、启停与工作台

需要 Python 3.10+。在解压后的包根运行 python Install.py，先查看目标、版本与是否需要备份；确认后运行 python Install.py --install。

默认检查个人 Codex 的 skills 根；使用其他 Agent 或自定义用户区时，传入 --skills-root 与 --user-area。检测到主 Skill 时，将本包放入用户区的 addons/letsgal-extension-design/<版本>/；没有主 Skill 时安装为独立 Skill，手册保留在其 docs/README.md。

主包支持自动接入时，安装完成后在用户区 workbench/MANUAL.html 的“创作参考”中打开本包。主包较旧时显示等待接入，安装结果保留；以后安装支持该接口的主包即可自动汇总。

更新与切换

相同内容重复安装只校验。相同版本的内容不同，安装器会停止；核对更改后使用 --replace，原文件保存在用户区 backups。安装另一版本保留原选版，显式 --select 才改为本次版本。已暂停的包继续暂停，--enable 才恢复。

新式包的状态保存在 addons/letsgal-extension-design/state.json。可请 AI 使用工作台的状态命令切版或暂停；例如在用户区执行：

python workbench/workbench_runtime.py state --user-area . --id letsgal-extension-design --enabled no

暂停保留文件，Wiki 只显示条目信息。主 Skill 更新及卸载保留这些资料。需要移除本包时，先暂停，再按安装记录备份并移出该 ID 对应的版本与登记；保留其他包和个人资料。

旧索引已有本包但没有机器可读状态时，需要先核原有启停及选版，安装器不会从自由文本猜测迁移状态。

设计练习与核对

先列出实际参数和作者常做的三五种操作，再让 AI 设计字段组织。你可以只提供自然语言；AI 应先核已有定义，避免草图创造不存在的功能。

以提示卡为例：作者经常修改正文与位置，偶尔调整时长。可比较“单页分组”与“外观／行为分页”。字段少且需同时对照时，单页便于连续阅读；行为选项较多时，分页更容易集中注意力。

预览应回答实际问题。卡片图示可以说明颜色和布局；时长、变量取值和运行事件需要在相应运行环境核对。页面可以采用共享预览、字段旁局部示意，或简单的参数摘要。

怎样提出修改

保留单页结构，把正文和位置放在开头，低频行为折叠。预设只改变位置和宽度，保留原颜色。请说明示意预览能验证什么，再按目标 SDK 实现。

怎样核对

  1. 能否找到常用字段，是否仍能访问其余参数。
  2. 能否看懂变量占位、只读状态和预设修改范围。
  3. 设计说明是否与真实参数和运行行为一致。
  4. 实现后由主 Skill 检查保存、绑定、权限与必要运行结果。

如果任务只需标准自动表单，就使用它；定制组件应解决具体操作问题。布局、分组数量和视觉样式按作品需求调整。

来源与适用范围

本包是社区整理的可选设计参考，适用于 LetsGal 扩展的设置页和方法检查器。布局方法可以跨版本借鉴，具体组件和 SDK 接口以目标宿主为准。

主要参考官方工坊“Studio 组件包演示”1.0.0，ID avg.official.studio-ui-showcase 的 README、Studio 入口、设置页及提示卡／评分检查器源码。该演示用于向扩展开发者展示组件组合，并非可直接用于游戏的成品。查阅时在工坊按 ID 定位对应版本，也可通过官方 MCP 的工坊源码读取接口核对。

本包归纳了分组、局部预览、自动表单与自定义控件组合等方法，并另写提示卡案例；未分发演示源码或素材。案例字段用于说明组织思路，实际字段以所做扩展为准。这里的设计取舍由本项目整理，官方 API 契约由官方资料维护。

布局与字段

从作者一次要完成的操作划分信息。把修改时经常一起核对的字段放近，把低频或专业字段收拢；字段数量本身不能决定必须分页。

情况 可用组织 取舍
字段少，作者需一眼比较 单页分组 连续可读，字段增加后页面会变长
外观与行为各自形成完整任务 按任务分页 减少干扰，跨页关联需要提示或共享预览
多项同结构记录 列表加详情或紧凑行 批量比较方便，但选中项和排序结果需要明确
参数多且用途分散 搜索或自动表单，补少量专题区域 覆盖全面，特殊业务关系需要解释

自动表单可以作为完整界面，也可承担剩余字段。字段需要联动解释、可视化选择或专用编辑行为时再考虑定制。分别说明各组解决什么任务，避免给相同字段重复入口。

小组件和局部订阅可减少无关刷新，也便于维护，但拆分粒度取决于真实重绘成本与代码规模。官方演示中的行组件是一种组织示例。

界面应在宿主主题中保持可读，选中、只读、无数据与错误状态需要可辨认。可用宿主组件和语义颜色，也可采用满足这些目标的其他布局。固定间距、分组数量和分页名称由实际内容决定。

预览与交互表达

先区分预览能回答什么：文字、颜色和布局常可在编辑期说明；真实变量值、运行事件、存档恢复需要运行环境。预览旁简短标明其范围，避免作者在图示中寻找尚未运行的效果。

选择预览位置

  • 持续对照颜色和位置时，可固定一个共享预览，减少来回寻找。
  • 参数与结果一一对应时，可把局部示意放到对应字段附近。
  • 修改结果主要是数据或调度关系时，状态表或摘要可能比仿游戏画面更清楚。

不必为所有页面制作预览。只有它能减少试错、解释关系或发现明显误配时才增加。

预设、变量与复杂列表

预设适合表达一组可复用选择，例如紧凑提示或居中对话。按钮旁说明会改哪些参数；与作者已有配置合并或整体替换由任务决定，实现时按主 Skill 的绑定保护与局部写回规则执行。

变量尚未求值时，可用文字占位或示例数据演示结构，并使占位与真实值易于区分。具体表达可以是标签、图例或预览旁说明。

评分区间、优先级或匹配列表存在顺序关系时，可显示当前顺序与一组代表输入的匹配结果。若后一项被前一项覆盖，说明是哪个条件造成；只有实际规则支持时才据此判断不可达。新增、删除、排序后的选中项和结果应连贯。

普通编辑可直接呈现结果；涉及较大范围的批量应用时，先让作者看清修改范围。反馈的强度与实际影响对应。

案例：提示卡编辑界面

假设扩展提供标题、正文、颜色、位置、宽度、显示时长和关闭方式。作者最常修改正文与位置，偶尔调整行为。

两种可改编方案

单页分组。 上方放文字与位置，中间展示卡片示意，下面收起低频行为。适合字段少、需要同时比较内容与外观的情况。

外观／行为分页。 外观页聚合文本、颜色和尺寸，行为页聚合时长与关闭方式；两页共享当前预览。适合后续行为参数较多，且两组可相对独立编辑的情况。

这两个方案都能结合自动表单。对正文、位置等需要特殊交互的字段定制，其余字段按实际需求保留标准表单；也可以全部使用标准表单。

形成可实施的说明

写清页面分组、首屏字段、预览内容、变量占位、无内容时的提示，以及预设影响的字段。字段 ID、类型、默认值、运行行为仍取真实 schema，不由界面草图凭空补出。

例如“底部紧凑”预设只改变位置和宽度；预览展示布局，时长在实际运行中核对。若用户希望预设连同颜色一起改变，应把这个目标明确纳入方案。

核对方案

请作者完成一次“修改正文、移动位置、调整显示时长”的任务，观察是否能找到字段、看到相关反馈并理解预设影响。确认用户原本关心的问题得到解决，再决定是否需要增加分页、摘要或更多定制。
