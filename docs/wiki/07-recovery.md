# 7. 排错、精确恢复与自测问题历史

## 写前准备与写后核对

准备覆盖本次改动的恢复点，优先使用已有项目历史、检查点或支持该操作的撤销。素材、独立源码等未被覆盖的文件需要另行备份。安装器的备份范围见[使用与备份说明](../../RISK-NOTICE.md)。

> 请只恢复本次试改的内容。先比较原恢复点与当前文件，列出会写回或删除的对象，保留试改之后我新增的内容；恢复后逐项读回，说明还存在的差异。

恢复以对象、字段或限定文件为范围。整工程恢复可能移除备份后新增文件，采用前需确认影响。后来编辑与恢复目标重叠时，先合并可确定的差异，再确认仍需取舍的部分。

## 按现象选择处理方式

| 情况 | 怎样处理 |
| --- | --- |
| 连接待批准、只读或权限被拒绝 | 在目标窗口确认所需权限；获得许可前可继续讨论和准备草稿 |
| 工具缺席、平台不在支持列表 | 核工具组、版本与当前接口提供的能力，选用已支持的路径 |
| 参数错误或自定义字段未被保留 | 按目标 schema 修正输入；自定义内容放在接口明确支持的数据位置 |
| 写入超时、结果未知 | 先读回目标和操作记录，确定已完成部分后再处理剩余项 |
| 删除后需要恢复 | `project_delete` 不支持普通 `history_undo`；数据行使用限定项目历史，素材使用其隔离区恢复入口，保留原 ID 和引用 |

版本选择和连接步骤见[第 2 章](02-connection.md)，数据行操作见[第 5 章](05-ui-data.md#数据表怎样核对)。

## 预览与构建

预览可以先交给 AI 通过 MCP 运行，核对实际对白和位置。窗口失焦或被遮挡后仍能运行时，可以继续，无需一直保持前台。

出现 `WINDOW_HIDDEN` 时，按 `reason` 处理：

- **`other-module`**：回到剧情预览所属模块；AI 可在当前任务允许时通过 `showPreview=true` 切换。
- **`window-hidden`**：先恢复最小化窗口。完全遮挡是否影响渲染还与宿主启动条件有关；当前 3.0 说明提到，启动后才启用 MCP 时可能受影响。
- **其他原因**：按当前宿主提示处理分离窗口、调试占用或界面遮挡等情况。

恢复后核对预览能否继续推进。仍失败时，保存具体原因、窗口状态和最小调用供反馈。

构建先检查配置、工具链并执行 dry-run，桌面平台按实际 `supportedSystems` 选择。随后分别核对产物是否生成、是否能在目标系统运行；交付时写明已完成到哪一步。

## 本项目自测问题历史

以下记录由本项目独立测试整理，供排查问题时参考。

- **适用范围**：每项记录对应所列版本、环境和样本。不同设备、配置与作品中的实际表现可能不同。
- **测试局限**：自测可能存在遗漏或判断偏差。“复现”和“复测通过”描述该次测试观察到的结果。
- **官方状态**：本节属于本项目的观察与判断。官方支持范围、问题确认及修复进展，请以官方说明为准。

### 3.0.0：历史现象与 r5 复测

2026-11-10 的 Windows 独立工程记录过以下现象，当次完整热修复标识未登记。官方 **r3** 公告随后说明了设置、调度和文件会话的相关修复；本项目于 **2026-11-12、11-13，在 3.0.0-stable-r5** 使用官方 MCP 复核，最新结果如下。

| 操作 | 早期自测现象 | r5 本轮结果 |
| --- | --- | --- |
| 扩展设置 reset | 官方内置壳改值后重置，默认标记或默认值读回有差异 | boolean、enum、array 的改值、重置和两步撤销通过；另测显式空字符串，重置与两步撤销均恢复预期值和默认态 |
| 修改入口数量后 undo | 修改入口数同时改变模式／策略，撤销仅恢复部分配置 | basic／linear 中改入口数保留模式、策略和图；撤销后完整配置与原状态一致 |
| 官方文件编辑会话 | 单处正文改动被旧正文覆盖，dry-run 为空 | 富文本单个文字节点改动进入两次 dry-run 并提交；撤销后全章内容、ID、绑定与 revision 和原状态相同 |
| GIF／WebP 素材处理 | 旧 Beta 样本出现撤销或删除时文件占用 | 两类独立样本的导入、尺寸读取、缩略图任务提交、导入撤销、原生删除、隔离区恢复及恢复操作的撤销通过 |

上述历史异常在本轮样本中均未复现。日常使用按声明、校验、提交和读回流程进行；遇到差异再保留具体输入与返回。复测覆盖上述 MCP 路径；其他调度模式、同章并发冲突及 SDK／界面／Player 的设置取值需按具体任务验证。详见[宿主验证范围](../../HOST-VALIDATION.md#300-r5历史问题复测)。

### 3.0.0 r5：预览窗口复测

2026-11-12，本项目在 Windows、3.0.0-stable-r5 独立工程中，通过官方 MCP 对预览可见性作了补充测试。

| 窗口条件 | 本轮结果 |
| --- | --- |
| 前台剧情页 | 定位与推进正常，实际对白随位置改变 |
| 被另一 Studio 首页窗口完全遮挡并失焦 | 定位、推进、从头运行和预览截图均成功；旧记录中的遮挡运行阻断本轮未复现 |
| 最小化 | 运行与截图返回 `WINDOW_HIDDEN / window-hidden`，符合当前宿主的渲染条件 |
| 恢复窗口 | 无需重启 Studio 或重连 MCP，即可继续定位和推进 |

本轮使用一个空首页窗口作遮挡，未改变 MCP 启用时机，也未覆盖双游戏工程连接等其他组合。结果尚不能确定旧现象的全部触发条件或具体修复版本。测试结束后原预览位置已恢复，剧情内容未改变。完整覆盖见[宿主验证范围](../../HOST-VALIDATION.md#300-r5预览窗口)。

### 参数校验的自测范围

2026-11-13，在同一 3.0.0-stable-r5 环境中，以目标 SDK 构建无副作用测试方法，完成 17 项 MCP dry-run。

| 检查内容 | 观察到的结果 |
| --- | --- |
| 正常参数 | 接受 |
| list 行数上下限、行内 number／boolean／enum 类型或选项、未知行字段 | 不符合声明的输入被拒绝 |
| data=null、自定义 validate 拒绝、list／data 绑定变量 | 被拒绝 |
| 顶层标量类型／数值范围／枚举、未知顶层参数 | 所测异常输入仍被接受 |
| list 行内数值范围 | 声明 1–3 时，99 通过 dry-run；实际写入后读回仍为 99，随后撤销成功 |

因此，提出扩展调用需求时，应让 AI 按方法声明核对类型、范围、枚举和可用参数，再使用宿主校验。此轮仅验证 MCP 接受或拒绝输入，没有运行异常参数；运行时如何取值要另查方法实现和执行结果。当前资料对不同字段的写入校验承诺有所区别，以上作为校验范围记录，尚无充分依据统一认定为官方缺陷。参数声明见[官方方法文档](https://docs.avg-engine.com/extensions/method)。

### 参考文档与接口差异

2026-11-13 的宿主 not-exposed 仍有两处旧说明，与当前接口不同：

| 主题 | 当前接口提供的信息 | 使用时怎样核对 |
| --- | --- | --- |
| 跨系统桌面构建 | 本机工具链返回 Windows x64、macOS arm64／x64 为支持目标 | 先查询实际 supportedSystems 和 dry-run，再核导出产物及目标系统运行 |
| 角色名称翻译 | l10n_read(names) 返回角色原名和目标语言译名 | 按名称翻译接口维护；界面文字、章节名等其他对象分别核支持范围 |

这属于资料一致性差异。选用能力时以当前 schema、SDK 类型和对应调用结果查证；本轮没有新增跨系统导出测试。

## 反馈问题要准备什么

提供 Skill 修订、Agent、Studio 完整版本与热修复标识、具体工具、最小输入、预期与实际结果，以及恢复状态。先核版本、权限和输入；符合目标接口支持范围仍出现差异时，整理可复现的步骤。

分享材料请使用脱敏片段或独立样本，去除私人作品、账号、令牌和截图中的个人信息。Skill 问题可在[仓库 Issues](https://github.com/recurse00-stack/letsgal-authoring-kit/issues)反馈；宿主现象按官方反馈渠道提交。
