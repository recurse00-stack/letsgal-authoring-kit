# 7. 排错、精确恢复与自测问题历史

## 写前准备与写后核对

准备覆盖本次改动的恢复点，优先使用已有项目历史、检查点或支持该操作的撤销。素材、独立源码等未被覆盖的文件需要另行备份。安装器的备份范围见[使用与备份说明](../../RISK-NOTICE.md)。

> 请只恢复本次试改的内容。先比较原恢复点与当前文件，列出会写回或删除的对象，保留试改之后我新增的内容；恢复后逐项读回，说明还存在的差异。

恢复以对象、字段或限定文件为范围。整工程恢复可能移除备份后新增文件，采用前需确认影响。后来编辑与恢复目标重叠时，先合并可确定的差异，再确认仍需取舍的部分。

## 按现象选择处理方式

| 情况 | 怎样处理 |
| --- | --- |
| 连接待批准、只读或权限被拒绝 | 在目标窗口确认所需权限；获得许可前可继续讨论和准备草稿 |
| 工具缺席、平台不在支持列表 | 核工具组、版本与当前接口提供的能力，选用已支持的路径 |
| 参数错误或自定义字段未被保留 | 按目标 schema 修正输入；自定义内容放在接口明确支持的数据位置 |
| 写入超时、结果未知 | 先读回目标和操作记录，确定已完成部分后再处理剩余项 |
| 删除后需要恢复 | `project_delete` 不支持普通 `history_undo`；数据行使用限定项目历史，素材使用其隔离区恢复入口，保留原 ID 和引用 |

版本选择和连接步骤见[第 2 章](02-connection.md)，数据行操作见[第 5 章](05-ui-data.md#数据表怎样核对)。

## 预览与构建

`WINDOW_HIDDEN` 先核具体 `reason` 和预览状态。最小化、锁屏、完全遮挡或停在其他模块可能影响渲染；窗口失去焦点后仍可能保持可见。恢复对应条件后再试一次。若可见窗口仍返回 hidden，保留窗口状态、reason 和最小调用供反馈。

构建先检查配置、工具链并执行 dry-run，桌面平台按实际 `supportedSystems` 选择。随后分别核对产物是否生成、是否能在目标系统运行；交付时写明已完成到哪一步。

## 本项目自测问题历史

以下记录由本项目独立测试整理，供排查问题时参考。

- **适用范围**：每项记录对应所列版本、环境和样本。不同设备、配置与作品中的实际表现可能不同。
- **测试局限**：自测可能存在遗漏或判断偏差。“复现”和“复测通过”描述该次测试观察到的结果。
- **官方状态**：本节属于本项目的观察与判断。官方支持范围、问题确认及修复进展，请以官方说明为准。

### 3.0.0：历史现象与 r5 复测

2026-11-10 的 Windows 独立工程记录过以下现象，当次完整热修复标识未登记。官方 **r3** 公告随后说明了相关修复；本项目于 **2026-11-12，在 3.0.0-stable-r5** 使用官方 MCP 定向复测，结果如下。

| 操作 | 早期自测现象 | r5 本轮结果 |
| --- | --- | --- |
| 扩展设置 reset | 官方内置壳改值后重置，默认标记或默认值读回有差异 | boolean、enum、array 的改值、重置和撤销通过；有声明的默认值与 `isDefault` 一致，无默认值的数组字段恢复原默认态 |
| 修改入口数量后 undo | 修改入口数同时改变模式／策略，撤销仅恢复部分配置 | basic／linear 中改入口数保留模式、策略和图；撤销后完整配置与原状态一致 |
| 官方文件编辑会话 | 单处正文改动被旧正文覆盖，dry-run 为空 | 单处文字改动持续保留，进入 dry-run 并提交；MCP 读回及撤销后全量块比对通过 |

这三项作为历史记录保留，当前用法按正常的声明、校验、提交和读回流程进行。复测范围为上述 MCP 路径；同章并发编辑冲突、其他调度模式，以及 SDK／界面／Player 的设置取值尚未在本轮验证。详见[宿主验证范围](../../HOST-VALIDATION.md#300-r52026-11-12-定向复测)。

## 反馈问题要准备什么

提供 Skill 修订、Agent、Studio 完整版本与热修复标识、具体工具、最小输入、预期与实际结果，以及恢复状态。先核版本、权限和输入；符合目标接口支持范围仍出现差异时，整理可复现的步骤。

分享材料请使用脱敏片段或独立样本，去除私人作品、账号、令牌和截图中的个人信息。Skill 问题可在[仓库 Issues](https://github.com/recurse00-stack/letsgal-authoring-kit/issues)反馈；宿主现象按官方反馈渠道提交。
