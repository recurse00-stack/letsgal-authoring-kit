# 5. UI、数据和扩展选型

## 先确定要解决什么

描述玩家要看到的东西、能进行的操作、数据从哪里来，以及退出或读档后应怎样。原生配置、可视化 UI、数据表、扩展程序和 Studio 设置页各有用途，不需要先决定“写一个插件”。

| 目标 | 先评估 |
| --- | --- |
| 标题页、菜单、地点牌、HUD | 原生配置或可视化 UI |
| 物品／角色条目与列表展示 | 数据表、绑定和界面动作 |
| 跨界面业务规则、复杂运行逻辑 | 现有扩展方法或程序扩展 |
| 供作者在 Studio 中编辑复杂参数 | 扩展的 Studio 设置页／检查器 |

先从[官方功能全景](https://avg-engine.com/studio/features)和对应文档确认能力，再按本工程版本与 MCP／SDK 查可用入口。功能宣传有该能力，不表示所有版本或所有接口都提供它。已有插件先读[匹配版本指南](06-personal.md)。

## 一个地点牌小练习

> 在独立练习章显示地点牌“旧车站”，停留后关闭并继续对白。优先复用工程现有 UI 和动作；不替换标题页、菜单或主题。请告诉我打开与关闭的入口，并验证关闭后对白仍能继续。

准备目标画面、尺寸要求及可用 UI 文档。预期得到界面入口、文字来源、显示／关闭动作和局部修改。检查位置、缩放、前后遮挡、退出后的输入控制；文档保存成功不等于按钮已能点击。

若本次需要独立 UI 文档，AI 应先读目标 schema，用实际返回的元素 ID 修改。整页替换必须保全原文、稳定 ID、状态、动画和引用，不能为改标题删掉其他组件。

## 数据表怎样核对

> 在练习数据表添加一个测试物品“车票”，价格 12；先读现有字段、类型和行 ID，保留其他行。将它显示到测试列表，再核对读回与界面取值。

数据表是结构化条目，行 ID 常被界面和剧情引用。新增／改值后核字段和引用；运行副本及存档行为另验。需要删除时先有覆盖集合文件的历史恢复点。`project_delete` 不支持普通 undo，恢复原行按限定历史恢复处理，不能把新建同名行当作保留原 ID 的恢复。

## 需要开发扩展时

> 现有方法不能表达这段规则。请先核目标 SDK 与公开接口，给出最小实现，保持原插件 ID、源码关联和现有设置。分别报告类型／构建、Studio 加载、方法调用和存读档检查。

普通玩家界面与供作者使用的 Studio 组件分开实现。参数和预设按目标 SDK 真实类型填写；Stable 3.0 的新增字段不能直接写进 2.9／2.8。调用方法前核类型、范围、枚举与资源引用，校验通过也不能保证业务条件正确。

状态分清作者配置、单槽存档、跨档数据和本次启动状态。恢复存档时可能重新经过逻辑入口，奖励／扣款等副作用需要按 SDK 的恢复语义处理。是否在 Studio、Player、Web 或导出中测试，分别报告。

重置扩展设置前读[设置 reset 差异](07-recovery.md#三类已确认差异)。看到“reset 成功”不能直接宣布默认态已恢复；显式设置为默认数值也不等于恢复默认态。
