# 6. 个人偏好、插件指南的建立与使用

## 三种资料放在哪里

`~` 指实际运行 AI 的用户主目录；WSL、远程环境或另一账号可能是不同目录。

| 内容 | 位置与用途 |
| --- | --- |
| 跨作品偏好 | `~/.letsgal-authoring/preferences/user.md`，例如文风、命名、窗口使用习惯 |
| 作品约定 | 工程已有规则或 `LETSGAL.md`，例如目标版本、已采用设定、启用插件 |
| 具体插件知识 | `~/.letsgal-authoring/plugins/<插件ID>/<版本>/SKILL.md`，必要参考放同目录 `references/` |

公共 Skill 只包含读取机制。更新、切换或卸载主包保留用户区；不要把私人内容直接改进公共 Skill。旧根目录 `user.md` 仍兼容，新旧都存在时应先比较冲突，不能创建空白文件遮住旧配置。

## 保存一条个人偏好

> 请把“修改现有工程前先读当前章节摘要”保存为我的 LetsGal 偏好，保留已有内容，写后读回。这个要求只针对 LetsGal 制作。

预期只在个人区补充实际要求，并能读回原有条目与新增条目。首次执行工程或扩展操作时主 Skill 应主动读取已有偏好；纯讨论按讨论范围进行，不因此自动修改工程。

## 给插件建立指南

准备插件真实清单 ID、版本／修订、可靠说明或源码，以及目标 Studio 版本。不要只提供工坊显示名称或随意取一个 ID。

> 请分析我指定的这个插件，核实 ID、版本和适用工程，为它建立插件 Skill。写清实际方法、参数、完整调用例子、存档影响及验证范围。保留已有资料，保存后从主 Skill 的查找路径读回入口与必要引用，更新索引。不要因此安装或启用插件。

AI 可按[插件写作模板](../../channels/stable/skills/letsgal-authoring/templates/PLUGIN-SKILL.example.md)整理有依据的用法。预期得到匹配版本的正文、必要引用及 `plugins/INDEX.md` 条目。未知参数标明待查，不能把猜测写成正式接口。

保存后的核对不止“文件存在”：应实际打开 SKILL.md，沿链接读取本任务所需引用，并确认与真实 ID／版本一致。安装运行插件与保存知识是两个动作。

## 平常使用时怎样确认读取

> 请用当前工程的这个插件完成车票规则。先核实际 ID／版本和启用状态，读取对应插件指南及本任务必要引用，再选择方法；告诉我采用了哪个版本的资料。

主 Skill 会通过索引或已确认 ID 的版本目录直接读文件，即使这个嵌套 Skill 没有出现在 AI 的全局技能列表中。无需再次注册、重复安装，也无需每次额外点名子包。

索引缺失时，AI 应定向检查已确认 ID／版本的目录。存在多个版本时以本工程实际版本为准，不自动取“最新”；版本冲突要核清，不能以升级插件来消除冲突。资料被明确暂停时保留并跳过加载；暂停协作附加包也不会因主包更新自动恢复。

如果 AI 只说“找到指南”却不知道方法细节，让它实际读正文及相对引用；若资料与真实接口不符，保留差异并按本项目已核实的清单、SDK／源码和运行证据处理。没有指南时仍可查可靠文档，不必为一次只读咨询自动建立资料库。
