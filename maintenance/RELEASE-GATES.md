# 0.1.0 正式发行检查入口

当前候选尚未通过发行门槛。先读 VALIDATION.md 和 validation-results.json，保留历史收据；不要把组件测试、客户端发现或静态分析换写成真实玩家验收。

1. 取得可通过类型检查的完整官方 SDK；复现及阻断说明见 SDK-BLOCKER.md。冻结 Stable 2.0.0 与 Beta 2.2.0-beta.1；若改基线，先记录新官方依据和范围。
2. 在不会载入用户真实扩展、作品、账号配置的隔离系统／用户环境验证两版宿主。同一工坊字节包都要导入、打开和操作；合成剧情都要走两条分支、回主线、改变量、存读档和 Windows 导出运行。
3. 完成 Codex、Claude Code、DSH 的真实模型任务及更新后新会话验收；仅使用合成目录。连接复用须获用户授权，不上传凭据，不带入私人 Skill 和历史。Cursor、Copilot 只标目录适配。
4. 用原生操作完成安装、检查、更新、卸载确认取消、文件夹选择，以及常用缩放下的路径／风险／错误提示验收。WPF 组件事件和截图不替代此项。独立 AI 两轮已经用完，无需再次启动；变化相关时另行确定复验范围。
5. 冻结版本后只重跑受改动影响的检查；同步核心、Skill、工坊清单、锁文件及说明。运行 build_release.py 刷新哈希，以新 ZIP 构建工坊；核对源码映射和实际第三方内容。测试目录、SDK、日志、账号、私人路径及旧备份不得进入清单。
6. 用 stage_publication.py 在全新目录准备核心与工坊源码，再对准确差异检查。正式打 tag／发布前核对全部阻断项已实际解除，保留 preview.7。
7. 发布 GitHub 0.1.0 后匿名下载、核对 SHA-256，再从下载资产做干净安装。同一已验收工坊包提交审核，检查简介、标签、源码仓库、开源设置及无私人资料的截图；分别记录 GitHub 已发布、工坊已提交、审核状态。

构建命令参见 workshop-guide/README.md（完整源码仓库中）。核心 ZIP 不含工坊源码。所有生成目录和 ZIP 必须全新；工具不会删除旧产物。工坊审核通过后的真实下载、内嵌 ZIP 提取和导入，作为单独后续验收。
